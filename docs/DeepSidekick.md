# DeepSidekick

> 一个坐在你旁边陪你打游戏、陪你聊天的 AI。它听得见你说话、看得见画面、说得出话，
> 单人陪玩是默认形态，开直播模式才接弹幕和礼物；除此之外什么都做不了。
> 本文只描述**当前实现**。数字按来源标注：本机实测写环境/日期，引用官方模型卡/论文/GitHub 的写来源，不把参考值当契约；可调数值以 `config.yaml` 为准。

## 0. 当前实现：世界书、游戏记忆、直播模式、TASK

这一节描述当前行为；数值以 `config.yaml` 为准。

### 0.1 启动与会话模式

```bat
.\run.bat              # 唯一入口：起 WebUI，浏览器打开 http://127.0.0.1:<webui.port>/
```

- **`run.bat` 不带任何参数**，只负责起 WebUI；配模型、选角色、开关直播、切桌面模式全在 WebUI 里点。
- WebUI 是父进程，`python -m sidekick` 是子进程；**runtime 只能从 WebUI 启动/停止/重启**，
  没有绕过 WebUI 直接跑 runtime 的入口。
- `config.yaml` 不存在：WebUI 启动时用 `sidekick/config/spec.py` 生成默认文件，顶部提示，不自动启动 runtime。
- 文件存在但读不了 / 空文件 / YAML 语法错 / 顶层不是字典：只提示，不生成、不覆盖；WebUI 可打开，runtime 不启动。
- 点「启动」前检查配置：brain 当前 profile 必须有 `base_url` / `model`；命中的厂商
  preset 要求 key 时还必须有 `api_key` 或已配置的密钥型 header。`tts.enabled=true` 且当前
  `tts.source` 的 preset 需要鉴权时，必须有 `tts.<profile>.api_key`；`edge`、TTS 关闭、
  `sessdata` 都不拦。`tts.source` 指向的 profile 或 preset 坏了也拒绝启动。
- **直播模式是「直播设置」页的一个开关**（`session.live`）。顶部不再单独选 solo/stream。
- **单人陪玩是唯一主线**：关（默认）时 `danmu_source=none`，没有观众/弹幕/礼物段；
  截屏保持开启；prompt 里**一个字的直播内容都没有**（预设里 `live: true` 的条目整段不注入）。
- 开（直播陪玩）：接弹幕/礼物/上舰；预设里 `live: true` 的条目照常按位置插入。
- 角色（形象 + 角色设定）在「角色设定」页选，**重启 runtime 后生效**；
  用户人设在「用户设定」页选，15 秒内生效。
- 角色资料（`persona/roles/<id>/profile.yaml`）坏了只在角色页标 ⚠，**不阻塞启动**；角色人设文本缺文件就是空。

### 0.2 Prompt 顺序

提示词拆成**三份互不相干的东西**：

| 层 | 存在哪 | 回答什么 | 换它要动谁 |
|---|---|---|---|
| 对话预设 | `persona/presets/<id>/preset.yaml` | 怎么做：场合、为什么开口、材料怎么读、输出成什么样、直播追加什么 | 所有角色共用 |
| 角色人设 | `persona/roles/<id>/persona.md` | 这个人是谁：来历、性格、口气、语气样本 | 只换这一个角色 |
| 游戏世界书 | `persona/games/<id>/` | 现在在玩什么：core + entries | 只换这一个游戏 |

一次请求的 messages 顺序（固定内容由代码填，预设的条目插在它们的缝隙里）：

```text
system  预设 start
system  角色人设 persona.md
system  预设 after_persona
system  用户档案
system  预设 after_user
system  游戏世界书 core
system  预设 after_worldbook
system  记忆·常驻      当前游戏状态/任务/最近剧情/NPC + 世界书 always + 最近记得的
system  预设 after_memory
user/assistant … 最近 N 条热窗（N = memory.history_max；user 是材料摘要）
system  预设 after_history
system  记忆·召回      今天是… + 你想起的往事 / 游戏里想起的
system  预设 after_recall_memory
system  游戏资料·召回  世界书命中的条目
system  预设 after_recall_worldbook
system  身份切换提示    （仅 role.id / user.id 相对上一轮发生变化时）
user    本轮材料（+附图）
system  预设 after_material
system  动作规则 + TTS 标签规则（跟随角色形象与当前 provider）
```

每一段之间的缝隙就是一个可选插入点。网页把这些固定内容画成锚点（角色设定 / 用户设定 /
游戏资料 / 长期记忆 / 交互历史 / 召回记忆 / 召回游戏资料 / 本轮互动消息），锚点不能移动；
条目拖到哪两个锚点之间，就落进哪个缝隙（`slot`），同一个缝隙里按列表（也就是 yaml 里
的书写顺序）排。

稳定性边界与缓存：

| 段 | 变不变 | 位置 |
|---|---|---|
| 预设 start → after_worldbook 之间的所有内容 | 换角色/改预设才变 | 稳定前缀，命中缓存 |
| 记忆·常驻 | 总结或换游戏才变 | 历史之前，跟着前缀吃缓存 |
| 历史 | 只追加，攒满才砍最老一批 | 中间 |
| 记忆·召回 / 游戏资料·召回 | **每轮都可能变** | 历史之后 |

所以放在 `after_worldbook` 及之前的条目要求「内容逐字稳定」，否则每轮都会让前缀缓存失效；
放在 `after_history` 及之后的条目怎么写都不影响缓存。

`role.id` / `user.id` 与上一轮不同时，在材料之前插一条 system 身份切换提示；
只改角色/用户内容、id 不变时不插，提示不会进入历史或气泡。

slot 是封闭小集合（`start` / `after_persona` / `after_user` / `after_worldbook` /
`after_memory` / `after_history` / `after_recall_memory` / `after_recall_worldbook` /
`after_material`），是条目落在哪个锚点区间的字段：网页按拖动后的位置归好缝隙，保存时写进去。
条目只声明 `slot`、`role`（system / user）、`live` 和正文；没有 EJS、没有变量、没有 depth 扫描。
`live: true` 的条目只在直播模式注入，网页上和普通条目排在同一个列表里，用「仅直播」标出来；
直播模式关着时一条都不出现。

人设文本来自**当前角色的设定目录** `persona/roles/<role.id>/persona.md`：没写就是空，
不从别的角色继承。`config.yaml` 只存 `role.id` 和 `prompt.id`。换角色要重启 runtime，换预设热更。
预设不存在时那一层就是空（不报错、不生成），`/status` 的 `preset_error` 会说明原因，
「对话预设」页的「查看完整提示词」能直接看到这一轮的完整 messages（§3.2.3）。

### 0.3 游戏世界书

```text
persona/games/<game_id>/
├─ core.md          # 常驻背景总览
└─ entries/*.md     # 按 keys/always 召回
```

entry front matter：

```yaml
---
title: 铁匠
keys: [铁匠, 老铁]
aliases: [老铁]
always: false       # true = 常驻注入
chapter: 2
spoiler: true
priority: 0
---
旧城的铁匠。
```

条目的 `id` 就是文件名（`blacksmith.md` → `blacksmith`）；front matter 里即使写了 `id` 也不参与寻址。

- 世界书条目由用户控制，任何时候可改，下一轮生效，不用重启。
- `always` = 常驻注入；非 always 条目按 `keys/aliases` 精确命中 + 本地向量语义召回。
- `chapter > 当前章节` 且 `spoiler: true` 不注入。
- `priority` 是召回同分时的排序键（越大越靠前）。
- 条目正文不截断；编辑器超过写死的提示阈值只提示，不阻止保存。
- 只按 `game.id` 找 `persona/games/<id>/`；没有单文件或任意目录路径。`game.id` 含路径时
  只取最后一段作为文件夹名，世界书与游戏记忆共用同一个 id。
- 整个目录可以打成 zip 带走 / 换机器导入（`GET /api/pack/export?kind=worldbook&id=<id>`、
  `POST /api/pack/import?kind=worldbook`），包里有 `manifest.json` + `core.md` + `entries/`。

### 0.4 游戏记忆

游戏记忆属于当前世界书，SQLite 带 `game_id`：

| 内容 | 行为 |
|---|---|
| `game_state` | 章节/场景/地点/目标/已知事实/未解问题/观察/**活跃任务**（标题 + 详情） |
| `plot_beats` | 剧情事件，新增或按 `supersedes` 修正旧条目；最近 `memory.game_recent_plot` 条常驻 |
| `npcs` | 角色卡，按名字/别名 upsert；前 `memory.game_npc_max` 个常驻 |
| `quests` | 已归档任务，存为 `memories.scope=game, kind=quests`；按关键词 + 向量召回 |

- 切换世界书时 `Memory.reload()` 按 `resolve_game_id()` 换 `game_id`；旧游戏剧情/任务不参与召回，切回去还能恢复。
- 陪玩记忆（`scope=live, kind=summary`）是**全局**的，不跟世界书切换；没有独立永久记忆/facts 层。
- 记忆的常驻/关键词由运行时自动决定，WebUI 不提供开关；内容/关键词可改。
- `observations` 是"还不确定、但值得留意"的短句，由总结写入；WebUI 不再展示/编辑游戏当前。
- 记忆库是 `state/deepsidekick.db`（SQLite，WAL），首次启动自动建表；`PRAGMA user_version` 记录 schema 版本。开发期 schema 固定为 `1`，改表不升版本，直接删除 `state/deepsidekick.db` 重建；版本不匹配时拒绝打开并提示删除数据库，不做迁移。
  WebUI 打开失败会返回 503 并显示真实错误，不会继续写旧库，也不会伪装成“记忆已关闭”。
  WebUI 用一把线程锁串行化记忆服务的打开/替换/统计；配置没变时 `force=True` 也复用现有
  连接，不会在状态采样时把旧 SQLite 关掉。
- 热窗 `messages` 带 `ts` 和 `game_id`；总结按最老连续 `game_id` 分组，切换游戏后旧游戏不会被写进新游戏。
- 总结连续失败 5 次会把最老一批压成兜底总结并删批，避免毒批永久阻塞后续总结；失败计数
  按当前批的 message id 记，换批自动归零。兜底只保留用户原话前 160 字，不丢整批时间线。
  关键词落库最多保留 8 个。
- `plot` 继承该批的 `start_ts/end_ts`；任务归档写当前时间，不再出现“时间不详”。
- 向量列在 WebUI 改 `content/title/keywords`（或 `scope/kind`）时清空，后台重新编码；缺向量时该条只走关键词。
- 补建向量不更新 `updated_at`，避免后台编码改变召回排序；向量缓存签名只含 SQLite
  `PRAGMA data_version` 与持久化的 `meta.vector_epoch`，普通消息写入不会让召回矩阵每轮全量失效。
- 召回列表直接按 `enabled=1` 查询后再 `LIMIT`，禁用的旧行不会挤掉活跃记忆；世界书读取
  报错时跳过本轮向量同步，避免把整本向量当成“条目已删除”清空。
- `worldbook_vectors` 只存内容指纹、模型身份、向量和更新时间；维度由向量 BLOB 长度决定，
  不再单独存 `dim`，避免出现和实际 BLOB 不一致的第二份维度。

### 0.5 任务标签

主回复可以带：

```text
<TASK>{"title":"找钥匙","detail":"从北门进，铁匠在等"}</TASK>
<TASKCOMPLETE>{"title":"找钥匙","keywords":["旧城","铁匠","钥匙"]}</TASKCOMPLETE>
```

- 活跃任务只有**标题 + 详情**，存在当前游戏的 `game_state.tasks`；没有状态/创建时间/别名，也不做向量。
- 玩家说完成时，从 `game_state.tasks` 精确匹配标题移除，归档为 `memories.scope=game, kind=quests`，这时才写关键词、做向量。
- 在写历史、action 提取、guard、TTS **之前**解析并剥掉；
- 标签绝不进入历史/气泡/TTS；
- 总结时带当前活跃任务，做补录/修正/完成；
- 完成只匹配唯一候选，多个不猜。

### 0.5.1 跨轮场景记忆

`brain.visual_memory_tag` 打开时，输出约束要求模型在回复末尾另起一行写
`<scene>不超过25字的当前画面关键状态</scene>`。`sidekick/brain/brain.py` 在任务标签、
动作提取、guard、TTS 和气泡之前**先剥掉标签**；超过 25 字截断，漏写/多写/写进
句子中间都静默降级，不破坏主回复。未闭合标签写在正文中间时只删标签、保留后面的正文；
从行首开始的未闭合标签按到文末都是场景处理。

写历史时，`[场景]` 行插在 `[画面]` 行之前：

```text
[材料摘要]
[场景]打女武神二阶段，血瓶剩2个
现在：...
画面：共 4 帧...
```

`[场景]` 与 `[画面]` 都保留：前者补 16 轮总结之间的短期视觉空档，后者保留时间戳可追溯。
标签内容不进 TTS、气泡、`said.jsonl`，也不作为独立 API 调用。关闭开关后不再要求模型写，
历史里也不再出现 `[场景]`；模型偶发写出的标签仍会被剥掉。

### 0.6 召回：向量 + 精确关键词

每轮只做一次本地 query 编码（最近 2 条用户发言；太短就补上一句/上一条回复），
三个池共用同一个向量；没有第二段 LLM 调用。短句补全只取用户原话：跳过
`[材料摘要]`、`现在：`、`弹幕：`、`画面：`、`冷场：`，并剥掉 `<用户名>：` 前缀。

- **向量**：`q · v`，向量已 L2 归一化；阈值 `memory.recall_min_score`（弱）和
  `memory.recall_strong_score`（强）。
- **关键词**：规范化后精确子串（含 aliases）；只认不同关键词的命中个数，不认出现次数；
  `score = strong_score + 0.02 × 命中个数`（写死）。
- **强相关**：向量达到强阈值，或关键词命中 → 不受 k 限制，每池最多写死 16 条。
- **弱相关**：达到弱阈值 → 填满该池 k 条（记忆/游戏/世界书分别是
  `memory.recall_episodes` / `memory.recall_game` / `memory.recall_worldbook`）；不足就少给。
- **常驻**：最近 `memory.recall_recent` 条总结、`game_recent_plot` 条剧情、
  `game_npc_max` 个 NPC、`task_max` 个活跃任务、世界书 `always`，不占动态召回名额。
- **时间意图**：`今天/昨天/前天/大前天/上周/这周/上个月/N天前/N周前` 先只在时间窗内找；
  窗内一条都没过阈值再退回全量。游戏记忆/世界书不参与时间过滤。
- **去重**：同一 id 多路命中保留最高分；同一件事的两条总结余弦 >0.90 时优先保留更晚的；
  动态候选也会和常驻块里的总结做 0.90 余弦去重，已出现在常驻块里的不再重复注入。
- 不设召回 token 目标、不设字符安全数、不截断；长内容由总结/世界书本身控制。
- 世界书与记忆同权：同阈值、同强相关规则、不做来源优先。
- 模型缺失/超时/空向量时本轮只走关键词 + 近因，不沿用上一轮召回结果。

### 0.7 WebUI

- `webui.host` 与 `stage.host` 只允许 loopback：`127.0.0.1` / `localhost` / `::1`；
  `serve_stage` 启动时还会再校验一次，防止手改配置绕过。
  `stage` 的 `app.js`/Spine 动态脚本会带同一个 `?v=` 版本号，升级后不会吃到旧缓存。
- 左侧导航：概览 → LLM 模型 API → **对话预设** → 用户设定 → 角色设定 → 游戏资料 →
  记忆与任务 → 听话（STT）→ 说话（TTS）→ 画面与节奏 → 直播设置。
  概览卡片显示运行状态、模型、TTS、麦克风、当前角色、当前用户和两类记忆；
  卡片下面是**启用控制**（所有功能开关 + 一个保存），再下面是运行日志。
- **保存是"每页/每模块一个按钮"**，没有全局保存：每个面板下的「保存」只写自己那几项
  （`PATCH /api/config` 只带这些路径，其余键原样留在文件里）。点了才写盘；
  热更字段下一轮生效，其余重启 runtime 后生效。
- **下拉选单只是浏览**（角色 / 用户 / 游戏 / LLM profile / TTS 声音）：选中就换页面内容，不写配置；
  点旁边的「保存」才把选择写进 `config.yaml`。离开页面再回来会回到**已生效**的那个，
  未保存的浏览不保留。新建预设/用户/LLM profile 前会先检查对应页的未保存修改，避免新建动作把草稿冲掉；
  角色页的 `rolePageDirty()` 已经包含 `DIRTY.config`，不再二次确认。
- **有未保存的修改时切页会弹确认**：取消留在本页；确定丢掉改动、按已保存的状态重画。
  页面顶部不再挂"有未保存修改"的徽标，也没有全局保存按钮。
- **所有「启用 xxx」都在概览页的启用控制里**（麦克风 / 语音识别 / 语音合成 / 截屏 /
  形象层 / 记忆 / 游戏资料），统一一个保存；直播模式仍在「直播设置」页。各功能页不再重复开关。
- 高级配置（`errors.*` / `state.*` / `webui.*`）只保留在 `config.yaml` 和运行逻辑里，
  不在 WebUI 显示或修改。
- 模型 API 页（一栏，从上到下）：

  填了服务端不认的值会 400，此时程序自动去掉它重试一次，`/status` 里 `brain.effort_dropped` 会标出来。
- `system_mode` 不在 WebUI 显示，配置默认 `auto`；多条 system 被网关拒绝时仍会自动合并重试。
- 画面与节奏页只保留两项：`capture.mode`（剧烈/平缓）和
  `capture.clarity_percent`（66.6 / 83.3 / 100）。剧烈 = 游戏/视频，1 秒/28 张；

### 0.8 已知边界

- 关键词不是语义检索；同一件事换说法会漏，靠 keys/别名补。
- 剧情/NPC 自动提炼可能漏/错，靠总结修正 + WebUI 改内容。
- 记忆库自动建表；测试使用临时目录，不碰正式库。
- DPAPI 只防文件被拷走/别的 Windows 用户；同机同用户可解。
- 隐私护栏是进程级：命中黑名单会停抓并清队列，但浏览器里的网银、邮箱、私聊页面仍是
  `chrome.exe`/`msedge.exe`，不能承诺“隐私全防住”。

# 第一部分 · 总

## 一句话

**三路输入 → 攒着 → 一次模型调用 → 一句话 → 同时念出来、写进气泡。**

没有 agent 循环，没有工具往返，没有第二个大脑。

## 一轮的时序（参考，环境/日期未记录，不当作契约）

```
t=0      你停嘴
t=+1.2s  VAD 判定「这句说完」，音频交给 STT
t=+2.0s  识别出文字 → 一条「我」事件进总线
t=+2.7s  调度器放行（短句多等 `scheduler.me_wait_short_ms`，长句立即）
t=+2.7s  同时取走这期间攒的截图（最多当前模式的张数上限）
t=+4.0s  模型回一句                       ← 脑 1.2–2.7s（带图也是这个量级）
t=+4.6s  TTS 首块音频到达                 ← 首音取决于厂商/网络
t=+4.6s  气泡第一页出现，嘴开始动
t=+5.0s  开始出声
```

**感知延迟 ≈ 4–5 秒**（从你停嘴到听见）。形象和气泡跟音频同时开始，不需要额外等待。

## 关键数字（本机参考，环境/日期未记录，不当作契约）

| 项 | 值 | 条件 |
|---|---|---|
| 脑延迟 | 1214–1762 ms（deepseek 官方）<br>2000–4800 ms（opencode 网关） | 人设约 5.6k 字 |
| 带图的额外延迟 | **0 ms**（deepseek）<br>+1 s（opencode） | 3–5 张截图 |
| 前缀缓存命中 | **90–93%** | 仅 deepseek 官方路由报明细 |
| 首音 | 取决于厂商/网络；逐家实测记录在 §12 清单 | 同一句话 |
| 一张截图的开销 | **578 token**（1280×720）<br>**314 token**（960×540） | 见 §1.3 的表 |
| 一轮图片构成 | 1–2 张高清（按清晰度缩放）+ 固定 1920×1080 网格 | 当前实现 |
| STT | SenseVoice int8（RTF 随机器变化，见 §1.2） | 4 线程 / CPU |
| 冷场触发 | 由 `cadence.quiet/normal/hype.idle_s` 决定 | 从「她上一次说完话」算起 |
| 内存 | ~200 MB | 常驻，无 GPU 占用 |

# 第二部分 · 分

## 1. 输入层

### 1.1 麦克风（`sidekick/input/mic.py`）

麦克风这一层只回答两件事：**你是不是在说话**、**这一句说到哪结束**。
判断规则在 `sidekick/input/vad.py`；设备形态在 `sidekick/input/devices.py`。

**不选设备**：始终用 Windows「系统 → 声音 → 输入」的默认设备，
和系统设置保持一致；改系统默认后重启 runtime（或拔插设备）即可生效。

**门限 = 固定基线 + 自适应噪声/峰值 + 用户百分比**：

```
固定基线   = 0.010
噪声底     = 最近 30 秒可用块的 p10
环境峰值   = 最近 10 秒可用块的 p90
基线门限   = max(固定基线, 噪声底 × 3.0, 环境峰值 × 1.15)
开口门限   = clamp(基线门限 × 门限百分比 / 100, 0.0025, 0.12)
续接门限   = 开口门限 × continue_ratio
```

| 门限百分比 | 安静房间的开口门限 | 效果 |
|---:|---:|---|
| 50% | 0.0050 | 更灵敏，小声/远距离用 |
| 75% | 0.0075 | 偏灵敏 |
| **100%（默认）** | **0.0100** | 平衡 |
| 125% | 0.0125 | 偏保守 |
| 150% | 0.0150 | 游戏声/电脑人声误触发时用 |

- 固定基线来自测试用 USB 麦克风实测：小声平均约 0.015–0.019、正常约 0.021–0.022、
  大声约 0.027–0.028；静音/游戏 p90 接近 0、峰值大多在 0.012 以下，所以 100%
  取 0.010 能覆盖小声，又不会因为游戏常态底噪误开。
  旧版手调的 0.015 是音响外放 + 耳机麦场景，偏高。
- 环境峰值参与开口门限：游戏声、电脑人声、音乐在最近 10 秒形成的持续峰值会把
  基线抬高；短促的枪响/爆音还有 `start_blocks` 兜底。
- 百分比只缩放门限，不改变切句/续接比例；设备收音偏小就调低，环境误触发就调高，
  不需要重填绝对阈值。
- 噪声底/环境峰值每 1 秒重算一次，用 `0.8 旧 + 0.2 新` 平滑；启动 2 秒内
  还没有估计值，直接用固定基线 0.010。
- 播放期与已判定为说话的块不参与噪声估计——否则她的声音和你的人声会把门限自己抬高。
- 环境声在已有估计后持续变响时，若连续超过 `max(10s, max_segment_s)` 且最近 200 块
  RMS 包络的变异系数 `< 0.28`（平稳底噪），会把这段强制回灌噪声估计并重置 VAD；
  真人长句包络起伏大，不会被当成底噪。
- 绝对上下限是安全网：环境噪声极低时不至于门限低到地板噪声一直触发。

开口/切句规则只有一份（`sidekick/input/vad.py`），线上采集与 `scripts/tune_mic.py` /
`scripts/probe_mic_cut.py` 共用它：

| 参数 | 作用 |
|---|---|
| `mic.mode` | 设备形态：`auto` 按默认输出设备名判，判不出按扬声器（保守） |
| `mic.gate_percent` | 门限百分比 50–150；100% 用固定基线（见上表） |
| `mic.silence_ms` | 多长的静音算说完（从**最后一声**起算） |
| `mic.min_speech_ms` | 说话时长（不含尾部静音）短于这个就丢掉 |
| `mic.continue_ratio` | 开口后续接门槛降到门限的这个比例（句中轻声不切断） |
| `mic.start_blocks` | 起手要连续几块过线（挡枪响/爆音） |
| `mic.max_segment_s` | 一直说个不停时硬切一段的时长 |

> `min_speech_ms` 量的是**纯说话时长**：说 1 秒 + 停 1.5 秒，`dur` 算 1 秒，不会因为带上了静音就过门槛。

### 1.1.1 播放期间麦克风怎么办

播放期**照常进 VAD**，不做整段丢弃。旧版"`is_playing()` 就吞掉整块"是当时没有
打断链路时的临时手段；有了 barge 之后，它会连"你是不是在说话"一起吞掉，反而让
打断和后续识别都失去依据，所以删除。

- TTS 漏音如果被 VAD 判成开口，`barge` 会用独立的 `barge_ms` 和播放参考能量决定
  是否停播；耳机模式按门限，扬声器 `barge.enabled: on` 时再要求高于播放能量比。
  扬声器播放期只在**起新段**时把门限额外抬到
  `clamp(max(门限, 当前播放能量 × barge.ratio × 0.85), 0.0025, 0.12)`，减少外放尾音被切成
  `ME`；已经开口的段续接仍按 `门限 × continue_ratio`，不会因为播放开始而被截断。
- 打断时 `speaker.speaking` 立即释放，流式 TTS 的 provider 生成器用 `aclosing`
  关闭，不再等 TTS 下载长尾结束。
- 她播的时候你说话，`speech_ms` 正常累计，调度器知道你在说；她停后你的话继续进 STT。
- 代价是 TTS 尾音/外放漏音可能被识别成一句话；如果经常发生，优先把输出切到耳机，
  或把 `mic.gate_percent` 调高（更保守）。

`/status` 的 `mic` 块能看出门限现在在哪：

```json
"mic": {"level": 0.031, "speaking": false, "error": null, "restarts": 0,
        "speech_ms": 0, "mode": "headset", "mode_cfg": "auto",
        "gate_percent": 100, "noise_floor": 0.0021, "noise_peak": 0.0048,
        "gate": 0.0100, "gate_continue": 0.0040}
```

启动时会打一行 `麦克风策略：headset（输出设备 耳机（示例设备））`，
噪声底就绪后再打一行 `麦克风门限：噪声底 0.0021 环境峰值 0.0048 开口 0.0100 续接 0.0040`；
设备断开会重开并重新判定形态，`restarts` 跟着加。

### 1.1.2 打断（barge-in，`sidekick/input/barge.py`）

她播音频时你说话 → **立刻停掉剩下的分句**。这是输入侧能力，不是模型能控制播放。

| 场景 | 行为 |
|---|---|
| 耳机，`barge.enabled: auto` | 她说时你说满 `barge.min_ms` → 她停（≤100ms，播放线程的轮询粒度） |
| 耳机，`off` | 不打断 |
| 扬声器，`auto` | 不打断；播放期照常进 VAD，漏音可能被识别 |
| 扬声器，`on` | 用能量比判据打断；可能被大音量游戏声误触发（建议戴耳机） |
| 打断后 | 这一轮剩余不说；历史只记已说出口的部分；**不道歉**、不算故障、不播兜底 |

判据：

```
耳机   ：麦克风电平 > 门限 × 1.5，持续 barge.min_ms
扬声器 ：再要求 麦克风电平 > 当前播放块能量 × barge.ratio（参考电平超过 300ms 未更新就用前一条）
```

- 门限乘 1.5、还要持续 `barge.min_ms`：打断应该比"轮到我说话"更难触发，咳嗽、碰桌、椅子响不该切掉她。
- 计数用**独立的 `barge_ms`**，与 `mic.speech_ms` 无关。旧实现拿 `speech_ms` 当打断判据，
  而它在播放期被 ducking 清零，两个功能共用一个状态 ⇒ 打断永远不可能触发（这就是当年整条链路被删的原因）。
- 字数不够时按 `max(0, barge_ms - 2 × 块长)` 衰减而不是清零：正常说话词间有 50–150ms 低谷，
  清零会让 `min_ms` 永远攒不满。
- 打断后 `barge.cooldown_ms` 内不再触发，避免一句话连续停两次。

被打断时出口按实际情况收口：

- 分段播放：已播完的分句算说过，剩下的不播；`SayResult.interrupted=true`，`spoken` 是已播部分；
- 流式播放：没有逐句边界，按"已播时长 / 估算总时长"折算已说文本（`cps` 是自校准的，误差约几个字）；
- 气泡停在已说到的那一页；`said.jsonl` 与历史只记已说部分；
- 一句都没说出去时，历史里这一对 user/assistant 直接删掉（`mark_spoken("")` 的语义）。

打断后你继续说完那句，`Scheduler.note_barge()` 让**下一次取材料**不受
`scheduler.min_gap_s` 限制（只放行一次），否则你要等她 6 秒才接话。

### 1.2 语音识别（`sidekick/input/stt/`）

**sherpa-onnx**（唯一后端）+ SenseVoice-Small（int8，默认模型），**固定 CPU 推理**：
官方 pip wheel 只有 CPU 版，`registry.build` 里 `provider="cpu"` 写死，配置里没有设备项。

| 指标 | SenseVoice-Small |
|---|---:|
| RTF（4 线程，模型卡参考） | **0.007–0.018** |
| 5 秒语音（同上） | **约 35–90 ms** |
| 模型体积 | 239 MB |

分两层：

- `sidekick/input/stt/engines/` —— 引擎层。`base.py`（`AsrResult`）、
  `registry.py`（YAML 模型表 → `OfflineRecognizer`）、`sherpa.py`、
  `postprocess.py`、`catalog.py`（下载清单 + 各模型的 RTF/内存/CER/WER）。
- `sidekick/input/stt/__init__.py` —— 门面。按 `stt.model` 选模型 → 失败按 `stt.fallback`
  降级 → 后处理 → 统计。`stt.model_dir`、`stt.fallback`、`stt.max_chars_per_sec`
  只保留在 `config.yaml` 和运行逻辑里，不在 WebUI 表单中展示/修改。
  对外是 `warmup() / analyze() / snapshot() / stats() / close()`。
- 模型在 runtime 启动时加载：换 `stt.model` / `stt.num_threads` 要**重启 runtime** 才生效。

`sherpa-onnx` 是**推理后端**，不是模型名。它能跑 SenseVoice / FireRedASR /
Paraformer / Qwen3-ASR / **Whisper** 等；加一套模型 = 在 `stt.models` 里加一段 +
把文件放进 `model_dir/<dir>`。内置的下载清单（[catalog.py](../sidekick/input/stt/engines/catalog.py)）：

| 模型 | 语言 | 下载 | CPU RTF | 内存 | AISHELL-1 | LibriSpeech | 特点 |
|---|---|---:|---:|---:|---:|---:|---|
| SenseVoice-Small | zh en ja ko yue | 163 MB | 0.007–0.018 | 600 MB | 3.0% | 2.1/4.8 | 非自回归；阿里 FunAudioLLM；标点/情绪/声音事件 |
| Paraformer-zh | zh en | 228 MB | 0.015–0.035 | 600–800 MB | 3.12% | 4.8/10.5 | 非自回归 CIF；阿里达摩院；工业级中文，带时间戳 |
| FireRedASR2-CTC | zh en | 521 MB | 0.06–0.17 | 1 GB | 3.20% | 3.1/7.2 | CTC；小红书；20+ 方言与口音，抗噪 |
| Whisper-large-v3-turbo | 99 语种 | 564 MB | 0.15–0.28 | 1.8–2.5 GB | 5.6% | 1.82/4.15 | 自回归精简版；OpenAI；Decoder 4 层，可替代原版 v3 |
| Whisper-small | 99 语种 | 639 MB | 0.12–0.20 | 800 MB | 8.7% | 3.5/7.6 | 自回归 Encoder-Decoder；OpenAI；多语种，中文稍弱 |
| FireRedASR2-AED | zh en | 839 MB | 0.35–0.65 | 2–3 GB | 3.05% | 2.4/5.8 | 自回归 AED；小红书；长句精度高 |
| Qwen3-ASR-0.6B | zh en yue | 879 MB | 0.08–0.15 | 1.5–2 GB | 3.42% | 2.11/4.55 | 自回归 Audio-LLM；阿里 Qwen；长上下文 + 热词 |

> 来源：下载体积来自 `catalog.py` 的发布包字节数；RTF/内存/CER/WER 来自模型卡、论文或 GitHub 发布说明，只作横向参考；"—" 是官方没给，不是 0。引用数据不要求本机复测，本机实测才需要环境/日期。
> **文件名不用写进配置**：`registry` 按 encoder/decoder/tokens 这类角色在模型目录里
> 自己找（int8 优先），所以加模型只写 `kind` + `dir`。
> Qwen3-ASR-1.7B 和 streaming-zipformer 没有加：前者 sherpa 没打包，
> 后者要另一个 OnlineRecognizer 的代码路径，而这条链路是"静音切段→离线识别"。

要点：

- **不在 Python 里重采样**。`stream.accept_waveform(sr, x)` 内部自带
  无混叠重采样（日志里的 `Creating a resampler: 48000 -> 16000` 就是它，
  每段一行，属于正常输出）。
- **warmup 跑一次空解码**，让 ORT 分配好内存池；加载在开麦之前完成。
- **崩了不会一崩到底**：连续 3 次识别异常 → 冷却 30 秒 → 自动复活一次（重新 load）。
  复活 3 次都失败就**永久停用**，日志打一大块红字，WebUI 顶部挂红条，
  `/status` 里 `stt.disabled=true`。只有重启 runtime 才会重新加载模型。
  冷却/停用期被丢掉的语音段单独计入 `stt.dropped_dead`，与队列满的 `stt.drops` 区分。
- **不流式**：断句仍然靠 `sidekick/input/mic.py` 的 `silence_ms`，必须等说完才有一整段。
- 后处理防幻觉（CTC 在噪声段的典型输出）：

  | 判据 | 阈值 |
  |---|---|
  | 真字数 | `< stt.min_chars`（标点不算；中文按字、英文按词） |
  | 语速 | `> stt.max_chars_per_sec`（同样按有效词元/秒） |
  | 复读 | 同一片段/单字占整句 ≥60% |
  | 多样性 | 8 字以上且不同字 <12% |

  `哈哈哈哈哈哈`（8 个）会丢，`哈哈哈哈笑死我了` 会留 —— 判的是"整句是不是在打转"，
  不是"有没有笑声"。

### 1.3 截屏（`sidekick/input/capture.py`）—— 累积式，不是每轮现抓

后台线程按当前节奏的间隔抓一张，按 1920×1080 最大框做 Downscale-Only Contain
（只缩小、不放大、不裁切，保持屏幕原有比例）。队列只存每帧的半尺寸缩略图 JPEG
（16:9 下 960×540）和一份 32×24×3 的 YCbCr 指纹；最新一张全分辨率图单独留一份，
供当前高清附图使用；语音快速截图时额外保留快速前的一张全图。
JPEG 固定 q85 4:4:4。开启底部台词条带时，每帧还多存一份底部 25% 的全宽
`bottom_jpeg`；60 帧的条带总量仍在 12 MB 以内。一轮开始时把这段时间的
**全部取走并释放**，不跨轮复用。

**节奏（WebUI 只保留这一项 + 清晰度）**：

| 节奏 | 截图间隔 | 每轮上限 | 历史帧 | 网格 |
|---|---:|---:|---:|---|
| `active` 剧烈（游戏/视频） | 1 秒 | 28 | 26 | 2×2 / 3×3 |
| `calm` 平缓（聊天/工作） | 6 秒 | 6 | 4 | 2×2 |

`active` 的 28 = 26 历史 + 当前高清 + 可选语音快速高清；没有快速帧时是 27 张。
`calm` 的 6 = 4 历史 + 当前高清 + 可选快速高清；没有快速帧时是 5 张。

模式还带各自的去重阈值与字幕权重：`active` 2.0/9/1.5，`calm` 3.0/14/1.0
（全局/块阈值、字幕权重）。这些值仍可在 `config.yaml` 手改。

**清晰度**（`capture.clarity_percent`）只影响当前高清和语音快速高清，不影响网格画布。
WebUI 三档显示：标准（66.6%，约578 token/pic）、高清（83.3%，约882 token/pic）、
原画（100%，约968 token/pic）；token 是 16:9 参考值，其他比例为估算。
百分比是**固定目标框**，不按当前屏幕分辨率再缩放：标准→1280×720，
高清→1600×900，原画→1920×1080；其他比例 contain 到同一目标框。

**拼图（`sidekick/input/composer.py`）**：`plan` 只选帧/算布局，`render` 在后台线程
解码缩略图、contain 到格子、编码。网格画布固定 1920×1080 上限，按源比例
contain：16:9 1920×1080、16:10 1728×1080、4:3 1440×1080；不裁切、不拉伸。
16:9 且源足够大时 2×2 单格 960×540、3×3 单格 640×360；源小于 1920×1080
或为 21:9 等比例时，画布和单格按实际源比例 contain，不强行放大到 1920。
历史新帧先以 2×2（16:9 960 格）进入；超过 16 帧后才把更老的帧降到 640×360 进 3×3。

图片顺序固定为：

```text
[当前高清（语音快速时是快速帧）] → [上一张高清]（语音快速时才有） → 2×2 → 2×2 → 3×3 → ...
```

整体从左到右**由新到旧**；高清帧不进入网格。`active` 的历史分组：

- 历史 ≤16：全部 2×2（16:9 且源足够大时单格 960×540），不足 2×2 的尾巴按源比例 contain 成 960×540 上限单张（4:3 源实际约 720×540）；2 张尾巴发两张单张，3–4 张仍拼 2×2。
- 历史 17–25：`n-9` 张走 2×2 + 最老 9 张走 1 张 3×3。
- 历史 26：最近 8 张走 2 个 2×2，最老 18 张走 2 个 3×3。

`calm` 只用一张 2×2；历史不足 4 张时按尾巴单张处理。
每格按实际缩略图 contain/letterbox，不拉伸。空格底色 `#1E1E1E` 并写「空」，
网格线 2px `#2A2A2A`。`[画面]` 会写「共 N 帧：最左 … 高清，之后为历史拼图
（…，左上→右下从新到旧）」。

**高清帧**：默认只保留最近一帧。语音触发 `capture_now()` 时，capture 线程会把
快速帧设为当前高清，并把快速前的那张全图以 `extra_jpeg` 留在前一帧；这一轮总共发
两张高清，不挤占普通历史帧。没有快速触发时只发一张。`FramePackMeta.high_res`
记录需要全分辨率的帧索引；`render(..., full_images={index: image})` 支持多张高清帧映射。

**底部台词条带（默认开启，自动判断，不再依赖节奏）**：
抓图时额外保存每帧全宽底部 25% 的 `bottom_jpeg`（q85 4:4:4，宽度按实际输出宽度），
`upper_diff` 取 32×24 YCbCr 指纹前 4 行（约上部 2/3），`bottom_diff` 取后 2 行
（约下部 1/3），都按去重权重（桌宠掩码、字幕 ROI）归一化，避免桌宠动画被当成
字幕翻页。`composer.plan` 在**原始连续帧**（不经过关键帧抽稀，避免把转场帧抽掉
后误判）的最新 3–6 张满足所有相邻帧 `upper_diff < 1.8` 且 `bottom_diff >= 6.0`
时，取最近最多 6 帧，把底部条带按当前高清帧宽度缩放后纵向拼接；高清帧仍在前。
条带宽度跟随清晰度（16:9、源 1920 时默认 1280；小源按高清实际宽度），
面积超过安全上限时自动拆成多张（例如 6 句在 100% 下拆成两张 3 句）。
条件不满足、帧宽不一致或缺少 `bottom_jpeg` 时回退普通拼图；
若条带 JPEG 在渲染阶段解码失败，只保留高清图。
`subtitle_strip_enabled` 默认开启，只用于显式关闭，写在 `config.yaml`，不在 WebUI 出现。
底部条带来自原分辨率底部裁剪，但缩放和 JPEG q85 4:4:4 仍是有损编码。

**模式之外的 `capture.*` 仍以 `config.yaml` 为准**：`capture.interval_s`、
`capture.max_frames`、`capture.dedupe`、`capture.ring_size`
和 `scheduler.min_gap_s` 都不在 WebUI 出现。

**去重阈值**：`capture.dedupe_global_threshold` / `dedupe_block_threshold` 同时满足才合并；
`capture.subtitle_roi_weight` 只加权底部两行。桌面窗每 1 秒把可见 alpha 包围盒写到
`state/desktop-<stage.port>.rect.json`，capture 线程读它给桌宠区降权；读不到就按不降权处理，
不影响抓屏。**120 ms 新鲜度**：`Scheduler.wait()` 在「我说话」或打断触发、且尾帧超过
`capture.capture_now_stale_s` 时，唤醒 capture 线程现抓一张；抓屏阻塞超过 120 ms 就直接
用队列现有帧，不拖住事件循环。

**隐私护栏与前台窗口**：capture 线程至少每 2 秒采一次前台进程（抓屏间隔更长时也单独醒来采样）。
命中 `capture.privacy_processes` 时跳过抓屏、清空队列和最新全图，并把 `privacy_active` 暴露到
`/status.capture`；材料写「当前是隐私保护窗口，没有截图」，不写标题。组材料前还会再看一次
隐私状态，命中就把这一轮已取出的图也丢掉。采样间隔最多约 2 秒：刚切到隐私窗口的极短窗口里，
已经取走的一轮旧帧仍可能发出，这是进程级近似的边界，不能承诺零延迟。这是**进程级**黑名单，
覆盖不到浏览器里的网银、邮箱、私聊页面；标题关键词也不能承诺全防住。
窗口不在隐私黑名单时，材料自动多一行
`[前台窗口] <标题> (<进程名>)`，标题只取前 40 字；不限定模式。
窗口标题用 `SendMessageTimeoutW` 读取，无响应窗口最多等 50 ms，不拖住 capture 线程。

为什么要攒：现抓只有「此刻」，模型不知道刚才发生了什么。攒着的一批是这几十秒的连续剧。

两个约束：

| 约束 | 值 | 行为 |
|---|---|---|
| 去重 | `dedupe: true` | 32×24 YCbCr 指纹，按 8×6 个 4×4 块比较；每像素取 `max(|ΔY|, 1.25×max(|ΔCb|,|ΔCr|))`。桌宠重叠块权重 0.08，底部两行乘 `subtitle_roi_weight`，桌宠块不参与字幕触发。全局差和最大块差都低于各自阈值才合并（菜单/暂停时省 token，也不会把静止画面说成动画） |
| 顺序 | 抓屏队列旧 → 新 | 取走时保持时间顺序；打包后图片从新 → 旧排列 |

### 1.4 弹幕（`sidekick/input/bili.py`）

`blivedm` 只读连接，源码 vendor 在 `vendor/`（PyPI 上的同名包是别的东西）。

- 只读：这条源里**没有发送函数**
- 昵称：带大号 `SESSDATA` 才是真名，否则 `a***b`
- 在线人数：另开 30 秒 HTTP 轮询 `room/get_info`（**必须带浏览器 UA**，不带 B 站返回非 JSON，人数就永远是 0）
- **没开播就没有弹幕**：B 站的弹幕流只在 `live_status=1` 时才有内容。所以程序会先查一次房间状态，
  没开播就每 30 秒看一次并打一行日志，**开播那一刻自动连上**，不用重启
- 运行时输入源只有 `bili` / `none`；没有假弹幕分支，测试直接构造 `Event`。

## 2. 调度（`sidekick/scheduling/scheduler.py`）

### 2.1 什么时候发起一轮

```
触发条件（任一成立）
├─ 你说话了        → 按 scheduler.me_wait_short_ms（短句多等）立刻发
├─ 弹幕攒够 scheduler.batch_events 条 → 立刻发
├─ 或攒够 scheduler.batch_s 秒 → 发
└─ 什么都没有      → cadence 的 idle_s 后发
```

**你正在说话时不起冷场**：你说的话要经过 `silence_ms + STT` 才变成事件，中间这一两秒
调度器看到的是"没有材料"。不拦的话，冷场计时会恰好在你说话中途到点，她对着空气说一句冷场话，
然后你那句才轮到（实测踩过：`[3] 冷场` 夹在两句「我说话」中间）。这条判断有 2.5 倍
`idle_s` 的保险丝：麦克风一直有底噪、被误判成"在说"时，最多拖到 `idle_s × 2.5` 也会开口。

「进场」不算触发：一条**只**有人进进出出的直播，不会因此起一轮（材料里照样会提一句「只有 N 个人进出」，
但那要等冷场到点）。触发只数能接话的：我说的话 / 弹幕 / 礼物 / 醒目留言 / 上舰。

### 2.2 三道闸门（什么时候忍住不发）

```
1. 静音模式          → 不起（在最前面，后面的都有副作用）
2. 最小间隔 `scheduler.min_gap_s` → 等（从**上一轮把 TTS 请求发出去**那一刻算起）
3. TTS 排队          → 思考不等播放；但上一轮没播完，这一轮的 TTS 请求发不出去
```

第 2 条治的是"连续短句"：你说一句短的 → 一轮 → 她回一句 → 你再说一句。
不留间隔的话，每轮回复都很短、很碎，而且常常只有一张图。

**被打断是一个例外**：她播到一半被你打断，你接着说的那句应当马上得到回应，
所以 `note_barge()` 会为**下一次取材料**放行一次（用掉就清），其余轮次照旧等 `min_gap_s`。

**思考不等播放**：上一轮把 TTS 请求发出去之后，这一轮就可以开始调模型了
（她的语音还在放也没关系）。只有「发 TTS 请求」这一步要排队——上一轮没播完，
这一轮的请求发不出去。所以一轮的周期 ≈ `max(思考, 播放) + scheduler.min_gap_s`，不是两者相加。

参考（假模型 0.8s / 假语音 1.6s）：第 2 轮的 brain 在 3.05s 开始，当时第 1 轮还在播
（播到 3.66s），第 2 轮的 TTS 请求等到 3.86s 才发出去。

`min_gap_s` 会被截图间隔抬起来（`max(min_gap_s, capture.interval_s)`）——
通常每一轮至少有一张新截图。`capture.enabled=false` 时不抬，按 `min_gap_s` 走。

### 2.2.1 从你停嘴到她开口，时间花在哪

```
你停嘴
 ├─ silence_ms 1200ms   ← input/mic：连续静音够久，切出这一段
 ├─ STT ≈1100ms         ← 识别；「我」事件的时间戳从这一刻算
 ├─ scheduler.me_wait_short_ms ← 只有识别出来短于 scheduler.me_short_chars 才加（可能是半句话）
 └─ scheduler.min_gap_s 闸门 ← 从上一轮 TTS 请求算起；上一轮刚说过就等它，反之立刻放行
```

短句 ≈ `mic.silence_ms + STT + scheduler.me_wait_short_ms`，长句少最后一段。
**`me_wait_short` 只在短句上生效**，而且经常被 `scheduler.min_gap_s` 闸门盖住 —— 所以不容易察觉。

`GET /status` 的 `scheduler` 里有三个数，专门看这件事：

```json
{"gate": "间隔不足", "gap_left_s": <剩余秒>, "material_due_in_s": <材料倒计时>}
```

- `material_due_in_s`：材料还差多久才"该说"（对应 `scheduler.me_wait_short_ms` / `scheduler.batch_s` / `cadence.*.idle_s`）；
  你正在说话时无法估计，返回 `null`
- `gap_left_s`：还差多久才允许开口（`scheduler.min_gap_s` 闸门）
- `gate`：现在被哪一道挡着
**改配置什么时候生效**：主循环每 15 秒看一次 `config.yaml`。提示词/身份/记忆相关字段热更：
`prompt.*`（预设 id）、`user.id`/用户档案正文、角色名字/别名/人设文本、`actions.md`、
`game.enabled`/`game.id`，以及 `memory.*` 中的检索/总结参数。
其中 `memory`/`game` 变化会重载记忆与召回；只改人设/身份时不会清空向量索引或重载历史。
`role.id` 本身仍要重启（运行中钉住启动角色）。
截图模式与调度参数也热更：`capture.mode` 会展开为间隔/张数/最大框，`capture.interval_s`、
`capture.max_frames`、`capture.resolution`、`capture.dedupe*`、
`capture.subtitle_roi_weight`、`capture.capture_now_stale_s`、
`capture.subtitle_strip_enabled`、`capture.privacy_processes`、
`scheduler.*`、`mode.*` 与 `cadence.*` 下轮生效；
改分辨率会清空队列并由 capture 线程重建 `Capturer`，调用线程不碰 dxcam。
`capture.enabled` 仍要重启。
其余设置——`guard.*`、`tts.*`、`mic.*`、`barge.*`、`stt.*`、`llm.*`、`stage.*`
（含 `cps`/`bubble`/`mode`/`autonomy`）、`errors.*`、`webui.*`、`session.live`、
`danmu_source`/`room_id`/`sessdata`——改完都要重启 runtime。

**间隔里你说的话、弹幕，全部攒着**，下一轮一次性发出去：
日志里会写成「我说话（3 段并成一轮）」。同一批里如果还有醒目留言/上舰，
`reason` 追加「（含醒目留言/上舰）」，仍以「我说话」开头。

**为什么思考可以先跑、TTS 请求要排队**：`Scheduler._gate()` 只拦最小间隔；
上一轮还没播完时，`Runtime.main_loop` 在创建下一轮 `talk` 前会 `await` 它，
不靠 `speaker.busy` 当闸门。模型快 → 轮次自然密；模型慢 → 自动并成一批。

### 2.3 冷场计时的基准

冷场基准取 `max(_consumed, _last_round, said.last_ts)`：
上一轮消费点、上一轮开始时间、她上一次说完话，三者取最晚的一个。
不单用 `said.last_ts`，也不单用上一轮开始；这样她自己的声音不会把计时吃掉，
而清空材料后的计时又能从最近一次动作重新开始。
如果麦克风只判到“在说话”、STT 还没产出 `ME`，冷场最多拖到
`min(2.5 × idle, idle + 6s)`；真正产出 `ME` 事件后才会重置基准。

### 2.4 一轮的材料长什么样（`sidekick/brain/material.py`）

材料只写**事实**，不写命令。有什么写什么，没有的整段省略；每一行都带真实时钟：

```
[现在]03:15:55｜陪了 37 分钟｜气氛 正常｜在线 12 人｜最近 5 分钟 9 条互动｜本轮 他刚说完话｜距你上次出声 26 秒
[你上一句]26 秒前：先躲一下嘛，血条都快没了
[这一段]最近 14 秒（03:15:41 → 03:15:55）
[前台窗口] ELDEN RING (eldenring.exe)
[画面]共 4 帧：最左 1 张当前高清；之后为历史拼图（3 帧 2×2，左上→右下从新到旧）。画面边缘的桌宠形象是你自己（不是游戏/视频角色）。
[用户名说的话]
  03:15:52 这boss怎么这么肉
[弹幕]4 条
  03:15:44 小张（叫你）：<角色名>你觉得这boss怎么打
  03:15:49 阿蓝：血不多了
[冷场]玩家已经 26 秒没有说话了，弹幕也停着，画面还在动。
```

几个字段是这一版新加的，作用都不是「催她说话」：

| 字段 | 作用 |
|---|---|
| `本轮 他刚说完话 / 弹幕攒够了 / 安静了一阵` | 告诉她**为什么轮到她**，由她决定接哪一路，材料本身不下命令 |
| `[你上一句]` | 防复读，也让你能接自己的话（「刚才说那谁……」） |
| `[前台窗口]` | 非隐私窗口自动出现；标题截前 40 字，没有开关 |
| 弹幕后的 `（叫你）` | 只有叫到你的弹幕才标；没标的可能只是观众之间聊天 |
| `[画面]这一轮没有截图` | 看不见就明说，别脑补血条、走位、界面 |
| `[画面]当前是隐私保护窗口，没有截图` | 隐私进程命中后队列已清空；不猜窗口内容 |

三路互不隶属，**材料里不下命令**——「该不该开口、接哪一路」由预设决定
（`rules` 槽的三种开口动机；`output` 槽的「什么时候写略」）。

冷场那句是 9 套说法轮着来的（`material._COLD`），{name} 取 `user.name`，
{screen} 按这一轮有没有画面变化自动填；**没有截图时会换成「你看不见画面」**，
不会替她编一个「画面停着」。同一句按固定节奏反复出现会显得像机器人。

材料里插图的顺序就是时间顺序，每张图前插一个时间标签：

```json
[{"type":"text","text":"<上面那段材料>"},
 {"type":"text","text":"[画面 03:15:43]"}, {"type":"image_url", ...},
 {"type":"text","text":"[画面 03:15:47]"}, {"type":"image_url", ...}]
```

## 3. 脑（`sidekick/brain/brain.py`）

### 3.1 形状

```
一坨材料 → 一句话
```

没有工具、没有循环、没有历史重建。模型是 `while` 里的一个函数，不是 `while` 自己。

### 3.2 请求结构

```
system  = 预设 start
system  = 角色人设 persona.md
system  = 预设 after_persona
system  = 用户档案（用户名字 + 用户设定；没写就不占这条）
system  = 预设 after_user
system  = 游戏知识（可选，按 config.yaml 的 game.id 插拔）
system  = 预设 after_worldbook（默认预设的「为什么开口 / 小目标 / 安全底线」就在这）
system  = 记忆·常驻（当前游戏/任务/剧情/NPC/世界书 always/最近记得的，放在历史之前）
system  = 预设 after_memory
messages = 最近 memory.history_max 条热窗（user = 当时的材料摘要，assistant = 你说的话）
system  = 预设 after_history
system  = 记忆·召回（今天是… + 你想起的往事 + 游戏里想起的）
system  = 预设 after_recall_memory
system  = 游戏资料·召回（世界书命中的条目）
system  = 预设 after_recall_worldbook（默认预设的「材料怎么读」就在这）
system  = 身份切换提示（仅 role.id / user.id 相对上一轮变化时）
user    = 本轮材料（+附图）
system  = 预设 after_material（默认预设的「输出契约 / 怎么说话才像个人」就在这）
system  = 动作规则 + 程序化表演 + TTS 标签规则（跟随角色形象与当前 provider）
system  = 画面场景记忆规则（仅 brain.visual_memory_tag=true；要求末尾写 <scene>）
```

**规矩、人设、输出契约全部在 system，user 里只有这一轮的事实。** 这不是排版偏好：
system 是稳定前缀，吃缓存等于免费；user 每轮都变，把规矩写进去就要每轮重新付钱，
而且模型会把它当成"这一轮的特殊要求"，反而不如常驻设定稳。

`PromptBuilder.build_messages()` 是唯一的拼装入口：固定内容按上表排，预设条目插进它们之间的缝隙；
`reply()` / `warmup()` / `sidekick/preview` 走同一个函数，所以预热、预演和真正发出去的是同一段前缀，
不会漂移。`prefix_messages()` 只负责稳定前缀那几条（到 `after_worldbook` 为止）。

**为什么拆成多条 system**：游戏知识换游戏才变，记忆/召回每轮都可能变，它们都不该让整段
人设前缀失效；拆开之后缓存边界更清楚，也方便单独看"预设有没有写对、人设有没有跑偏、
游戏资料有没有过期、记忆有没有写脏"。几条 system 的职责是硬的：预设回答"这一轮该怎么玩"，
人设回答"你是谁、你怎么说话"，游戏知识回答"你现在在玩什么"，记忆回答"你记得什么"，互不混写。

**user / assistant 的关系写在预设的条目里**：

- `assistant` 是角色名（`persona.bot_name`），只输出要说出口的那一句话；
- `user` 不是你，也不是用户，它是材料投递口；
- `user` 里可能同时有 `[<用户名>说的话]`、`[画面]`、`[冷场]`，直播模式下再加 `[弹幕]`；
  只有 `[<用户名>说的话]` 才是用户在跟你说话；
- 历史里的 `assistant` 是你以前说过的话，历史里的 `user` 是当时的材料摘要，不是用户的原话。

#### 3.2.1 插入点怎么切

固定内容按「角色 → 用户 → 游戏 → 记忆 → 历史 → 召回 → 材料」排，每两块之间是一个可选插入点。
「用户设定之前」和「角色设定之后」是同一个缝隙，所以只暴露 **N+1** 个缝隙，不做重复的"前后"。
网页把这些固定内容画成锚点，条目只能在锚点之间拖；文件里每条只记自己落在哪个缝隙（`slot`）。

| 缝隙 | 夹在什么之间 | 适合放什么 | 影响缓存吗 |
|---|---|---|---|
| `start` | 一切之前 | 场合（这是什么场合） | 是：要逐字稳定 |
| `after_persona` | 角色设定 ⇢ 用户设定 | 需要紧跟人设的补充 | 是 |
| `after_user` | 用户设定 ⇢ 游戏资料 | 用户相关的额外规则 | 是 |
| `after_worldbook` | 游戏资料 ⇢ 记忆 | 开口动机、小目标、安全底线 | 是 |
| `after_memory` | 记忆 ⇢ 历史 | 只跟记忆有关的提示 | 是 |
| `after_history` | 历史 ⇢ 记忆召回 | 每轮要换的提醒 | 否 |
| `after_recall_memory` | 记忆召回 ⇢ 游戏资料召回 | 怎么用「想起的事」 | 否 |
| `after_recall_worldbook` | 游戏资料召回 ⇢ 本轮材料 | 材料怎么读、这一轮怎么开局 | 否 |
| `after_material` | 本轮材料 ⇢ 动作规则 | 输出契约、去八股判据、任务标签 | 否 |

紧挨着的几块**必须连续**、没有可插的地方：

- 角色设定和用户设定之间没有别的固定内容，所以「角色后」=「用户前」；
- 历史是一段连续的 user/assistant，不允许往中间插——插了就等于把"上一句"改成别的东西；
- 记忆召回和游戏资料召回是同一轮算出来的两个块，拆开是为了能在中间插提示，不是让它们分开召回。

#### 3.2.2 主动性是怎么写进去的

材料给什么就接什么，没人说话就回「略」，会像应答机。默认预设在 `after_worldbook` 的条目用三样东西解决：

1. **三种开口动机**：接（他在跟你说话）、反应（画面里出事了）、
   自己的事（你心里揣着的事、对游戏的看法、想问的问题）。每轮开口至少带一个"你自己的东西"：
   一句判断、一个赌、一个主意、一句吐槽、一个想问的问题。
2. **你不当解说员**：明确禁止"他在打怪、血条在掉、画面里有个菜单"这种复述，
   并给了一句正向手感（先有判断，再带一句画面；不能反过来）。
3. **你每场给自己找个小目标**：让他笑一次、猜中他下一次怎么死、骗他试个作死打法、
   让他请饭……目标不用宣布，也不用每轮提；有机会就推一把。这条让行为跨轮有连续性，
   而不是每轮重新投骰子。

连续性还有两个底座：`[你上一句]`（防复读、能接自己的话）和两层记忆
（最近记得的/热窗里最近 `memory.history_max` 条）。参考三轮：她第一轮押「赌一顿饭」→ 第二轮他说过了 →
她回「行吧，饭记账上」→ 第三轮接着损他「后面别翻车打自己脸」。这不是靠随机台词能做到的。

沉默仍然是合法选项（`略`），但理由变了：不是"没人给你派任务"，而是
"刚说完/他在关键操作/画面看不清/确实不想说"。材料里的 `本轮` 只回答"为什么轮到你"，
不回答"你该不该开口"——后者永远归预设。

`after_recall_worldbook` 里的「材料怎么读」负责**防脑补**：没有 `[画面]` 或写着「这一轮没有截图」时，
不许提血条、走位、界面、卡住；没写的时间、次数、承诺不许编；弹幕只在这轮出现，
不许加「又问」「刚才也问过」。这是陪玩真实感的底线——说错一句比少说一句伤得多。

#### 3.2.2.1 去八股写在 `after_material`

「鱼八股」这类腔调的根不是词，是**把说话当成交付**：怕这一轮什么都没交出来，
于是每句话后面挂个凭据，证明听见了、在场、没白待着。所以默认预设在这里按这个顺序写：

1. 根因一句：这一轮不需要证明你听见了，听见了就往下接；
2. 三条自检判据：删掉会少知道什么 / 是在回他还是证明在回 / 有没有具体的东西；
3. 具体行为：不给人打分、不称重量、不宣告在场、不竖靶子、不讨点头、说完就停；
4. 频率约束：上一轮的开头词和句尾语气词这一轮换掉。

判据写成可执行的检查，而不是一串禁词：禁词表会先把它自己送进上下文（说「不要提 X」常常等于提 X），
而"删掉这句对方会少知道什么"这种判据可以当场做完。

#### 3.2.3 在网页里看完整提示词

「对话预设 → 条目」右上角有「查看完整提示词」：`GET /api/prompt/preview` 起一个短命子进程跑
`python -m sidekick.preview`，把 `# 预设 …` 摘要和请求体（key 不在请求体里）原样显示出来。
用已保存的配置现拼一次，材料是一份固定样例（一条「我说话」+ 两条弹幕 + 15 秒窗口），
命令行的 `scripts/show_prompt.py` 是同一个入口。预演把 `state/deepsidekick.db` 复制成临时快照再读，
召回/世界书写 `last_used_at`、向量都只落在快照里，不会和 runtime 抢正式库的写锁。
子进程每次用独立临时文件；请求取消/页面关闭时会杀掉子进程并清理文件，不会留下后台预演。

#### 3.2.4 游戏知识包（插拔）

游戏资料单独放在 `persona/games/`，作为主 prompt 的一个稳定 system；一个游戏一个目录包：

```yaml
game:
  enabled: <bool>
  id: <game_id>      # → persona/games/<game_id>/core.md
```

换游戏只做三步：

1. 新建 `persona/games/<新id>/`（目录包：`core.md` + `entries/`）；
2. 在 WebUI「游戏资料」页的下拉里选中它（下拉只显示 id）；
3. 保存。下一轮 `Worldbook` 重新读取并注入，不用改当前角色的人设文本。

`game.enabled: false` 或文件不存在时，`prefix_messages()` 自动跳过游戏 system，
消息退回「人设 + 用户 + 记忆」；不会报错、不会影响主 prompt。
坏掉的 entry 会被跳过，不阻塞其他条目；错误摘要汇总在 `/status` 的
`game.error`，不会被静默吞掉。

没有内置示例；`persona/` 整体不入库，真实游戏的资料包、`roles/`、`users/`、`games/`
都放本机照常能读。

写法约定见 `persona/games/README.md`：第二人称、公开资料、剧透分区、不写输出格式/安全底线。
`Worldbook` 按需读取：`core_text()`、`always_entries()`、`recall()` 各自触发一次 `_read()`，
文件 mtime 变了就重读；不是"每轮只 stat 一次"。配置改了 `Runtime._refresh()` 会调
`brain.reload_config()` 换包。

### 3.3 模型来源

只支持 OpenAI chat/completions。`config.yaml` 里一个 profile 就是一家服务：

```yaml
llm:
  source: <profile>          # 当前用哪份 profile
  common:                    # 所有 profile 共用
    warmup: <bool>
    timeout_s: <秒>
    system_mode: auto | multi | single
  <profile>:
    base_url: https://api.example.com/v1
    model: <模型 id>
    api_key: sealed          # 真值在 DPAPI 密钥库；可空
    temperature: <0–2>
    reasoning_effort: <字符串；空 = 不传>
    headers: {}              # 任意静态请求头，空值 / sealed 跳过
    body: {}                 # 额外请求体参数；WebUI 不显示
```

| 字段 | 写什么 | 谁读 |
|---|---|---|
| `base_url` | base 地址，或完整 `/chat/completions`；查询参数保留 | `LLMClient.url` / `models_url` |
| `model` | 模型 id | 请求体 `model`、`/models` 下拉、状态与日志 |
| `api_key` | Bearer key；可空 | `Authorization` 头（可被 `headers` 覆盖） |
| `temperature` | 采样温度 | `body_defaults()` |
| `reasoning_effort` | 推理强度；空 = 不传 | `body_defaults()` |
| `headers` | 任意请求头；空值 / `sealed` 跳过 | `LLMClient.headers()` |
| `body` | 额外请求体参数 | `body_defaults()` |

`sidekick/config/llm_presets.py` 存内置厂商的默认地址、模型和静态请求头。它只用于：

- 生成默认 `config.yaml`（默认 profile 由 `DEFAULT_ID` 一行决定）；
- WebUI 新建 profile 时按名字预填 `base_url` / `model` / `headers`；
- 启动闸门判断该厂商 `needs_key`（本地无鉴权服务写 `false`）。

它不进运行时：`LLMClient` 只认 profile 字段，不 import 这个模块；preset 改名或删除
不会影响已经保存的 profile，也不需要运行时 fallback。

新增一家 OpenAI 兼容厂商：在 `PRESETS` 里加一条（`label` / `base_url` / `model`，
可选 `headers` / `needs_key`）→ 跑 `unittest discover` → 重启 WebUI →
模型页「Profile 名称」填 preset 名点「新建」。不需要改 `llm.py` / `form.py` /
`app.js` / `index.html` / `spec.py` / 测试文件。

- 本地 Ollama / LM Studio / vLLM / llama.cpp server 暴露 OpenAI 兼容 `/v1`：
  加一条 `needs_key: false` 的 preset，或直接建自定义 profile 留空 key。
- 非 Bearer 鉴权或任何额外请求头写 profile 的 `headers`；需要保密的值走 DPAPI 密钥库。
- OpenCode 网关要求浏览器 UA 和 `x-opencode-session`，这两条放在该 preset 的
  `headers` 里，新建时自动带出。
- 非 OpenAI wire（Anthropic 原生 / 进程内 llama.cpp）不在支持范围。

### 3.4 缓存设计

DeepSeek 的前缀缓存逐 token 从头比对，所以原则只有一条：**越稳定的越靠前**。

```
预设 start（几乎不变，直播条目只在直播模式）
→ 角色人设（几乎不变）
→ 预设 after_persona → 用户档案
→ 预设 after_user → 游戏知识（换游戏才变）
→ 预设 after_worldbook
→ 记忆·常驻（当前游戏/任务/最近剧情/NPC/世界书 always/最近记得的；总结或换游戏才变）
→ 历史（只追加；总结时才砍掉最老一批）
→ 预设 after_memory → 预设 after_history
→ 记忆·召回 + 游戏资料·召回（日期/召回；每轮变）
→ 预设 after_recall_memory → 预设 after_recall_worldbook
→ 本轮材料（每轮变，图在最后）→ 预设 after_material → 动作/TTS 规则
```

- 常驻块放在历史之前：它和稳定前缀一起命中缓存；日期/召回每轮变，必须留在历史之后。
- `start` … `after_worldbook` 之间的预设条目属于稳定前缀（放在这里的条目必须逐字稳定）；
  `after_history` 之后的条目怎么写都不影响前缀缓存。
- 历史**不滑动**：攒满 `memory.history_max` 条才一次性砍掉最老 `memory.summarize_every` 条；切游戏时只砍最老同一 `game_id` 段，可能更短。每轮滑窗会让前缀每轮都变，整段失效。
- `memory.history_max` 与 `memory.summarize_every` 建议填偶数；代码会向上取整到偶数，并保证 `summarize_every < history_max`，避免拆散 user/assistant 对或把历史清空。
- 启动时发一次 8 token 的请求预热 system 前缀；`warmup()` 用的是**完整**
  `prefix_messages()` + 输出约束（预设 start/after_persona/after_user/after_worldbook、人设、用户、游戏，
  游戏没配就少一条），不是只发人设——否则第一次说话还要重算后半段。
- 图只出现在最后一轮的材料里，**不进历史**；历史里保留的是 `[材料摘要]`（结构压缩后的文本，不按字符截断），画面只留行内时间；开了场景记忆时另加一行 `[场景]`，画面行仍保留。
- **断点只在「攒满 `memory.history_max` 条消息压一次总结」那一刻**：按 `memory.summarize_every` 压；换游戏也按最老 `game_id` 组切批。

### 3.5 出错怎么办

一轮正常最多 **2 次请求**（原始 + 重试 1 次）；能力探测（`reasoning_effort` 降级、
多 system 合并）共享一个总上限 `max(2, attempts + 1)`，避免极端故障下 4 次串行请求。
分类决定要不要重试：

| 故障 | 判据 | 重试 | 之后 |
|---|---|---|---|
| 网络断 / 超时 | 异常 | **1 次**（`errors.retry_delay_ms` 后） | 兜底话术；最终异常不带上一次 HTTP 状态，避免被误判成 4xx |
| 5xx / 429 | status ≥ 500 或 429 | **1 次** | 兜底话术 |
| 4xx | 400–499（429 除外） | **不重试** | 兜底 + 记录错误 |
| 400/422 点名 `reasoning_effort` | 错误正文含该字段名 | **去掉后 1 次** | 正常继续；`/status` 标 `effort_dropped` |
| 400/422 只收一条 system | 错误正文含 `system` | **合并后 1 次** | 正常继续；探测结果 10 分钟后自动失效，避免永久降级 |
| 400/422 是 `body` 的其它额外参数 | 错误正文点名 | 不自动剔除 | 报错；改 `config.yaml` |
| 400/422 是 `temperature` | 错误正文点名 | 不省略 | 报错；`temperature` 是页面必填 |
| 200 但 JSON 坏 | 解析异常 | **1 次** | 兜底话术 |
| 正文为空（含推理吃光配额） | `message.content` 空 | **1 次**（`errors.retry_delay_ms` 后） | 兜底话术 |
| 回了「略」 | 命中静默词表（去掉发声标签后只剩「略」也算） | 不重试 | **合法沉默**，不说话，不算故障 |

**兜底话术的三道闸**（`sidekick/output/fallback.py`），防止直播间变成复读机：

```
连续失败第 1 次 → 道歉（洗牌袋，不重复）
连续失败第 2 次 → `errors.fallback_cooldown_s` 内不道歉
连续失败第 3 次 → 道歉一次
连续失败第 4 次起 → 闭嘴，只写日志，/status 标 degraded
恢复且中断达到 `errors.recover_say_s` → 说一句「我回来了」
```

「连续 3 次」数的是**跨轮**，不是一轮里试 3 遍。按 `cadence.*.idle_s` 的冷场节奏，
这等于「挂了一分钟之后就别再道歉了」。

## 4. 记忆（`sidekick/memory/history.py` + `sidekick/memory/long_term.py`）

### 4.1 长期记忆与热窗

| 层 | 容量 | 位置 | 变化频率 |
|---|---|---|---|
| 陪玩总结 | `memory.recall_recent` 条常驻，其余按向量/关键词召回 | 历史之前常驻块 / 历史之后召回块 | 按 `memory.summarize_every` |
| 游戏记忆 | 最近 `game_recent_plot` 条剧情、`game_npc_max` 个人物常驻；归档任务按需召回 | 历史之前常驻块 / 历史之后召回块 | 总结/切游戏 |
| 游戏当前 | 当前游戏的 state + 活跃任务 | 历史之前常驻块 | 总结/切游戏 |
| 热窗 | `memory.history_max` 条（user 是材料摘要，assistant 是她的话）；总结失败 1–4 次时临时放宽到 +10 条 | messages | 每次说话 |

没有永久记忆/facts 层：稳定身份放用户档案，其余事实写进总结正文。
这些记忆都用**第二人称**：动态块是「你记得的事」，`messages` 里的 assistant 是
「你说的话」，user 是「当时的材料摘要」。

`memory.enabled=false` 时不建 SQLite：`InMemoryHistory` + `NullLongTerm`，
短期对话仍在，长期记忆为空。

### 4.2 压缩规则

```
历史攒满 `memory.history_max` 条 → 一次独立 API 调用
                → 产出 {segments:[{op:new|merge,...}], game}
                → 同一事务里写总结/游戏记忆 + 删掉这批历史
                → 新增/合并的总结丢给后台编码向量
```

- 默认 `history_max=40`、`summarize_every=16`：20 轮热窗，每 8 轮总结最老 16 条。
- 热窗消息带 `game_id`；总结只取最老连续同一个 `game_id` 的一组（可能不足 16 条），
  切游戏后旧游戏不会被写进新游戏；旧组用旧游戏的 `game_state`。
- 输入 = **只这一组**材料摘要 + 她说的话；system 2 是最近 5 条已保存总结（merge 只能指向这些 id），
  system 3 是这一组所属游戏的状态。尚未压缩的尾巴不混进来：尾巴里的时间会晚于这一批的
  `start_ts/end_ts`，混写会让陪玩记忆显示的时间慢半小时；尾巴等自己的批次再总结。
- 每条总结按“事情”分，1–5 条；长度不设目标、不设硬上限、不截断；
  必须保留关键原话、数字、地点、期限、约定、情绪变化和未解决的事。
- `segments` 是陪玩记忆：陪玩过程、他的状态/情绪、关系、约定、换游戏；游戏细节只写对关系有意义的。
  `game` 是游戏记忆：剧情/NPC/任务/地点/机制；同一事件允许两边各写一句，但不要两边都写全。
- `keywords` 只收**有信息量的名词性实词**，专有名词优先（人名/地名/作品名/特定道具/Boss/任务/梗）；
  禁止动词、形容词、代词、语气词和“游戏/任务/今天/聊天”这类到处都成立的泛词，最多 5 个，宁缺毋滥。
- `op=merge` 重写整条（不是追加），压缩早先细节、保留结论；`target` 不在最近 5 条里按 `new`。
- `segments: []` 是合法空段（确实只有寒暄）；空段但 game 有内容时仍写 game 再删历史；
  segments 非空但 content 为空按失败处理，不 commit、不删历史。
- 活跃任务只写进 `game_state.tasks`（标题 + 详情）；`action=complete` 时归档成
  `memories.scope=game, kind=quests` 并写关键词，归档后才有向量。
- 总结请求固定 `reasoning_effort=high`，只对**首个正文 token**设 25 秒超时：25 秒内没等到
  正文才失败；收到正文后不再设总超时，长总结由上游自己结束。思考内容不算首字。
  当前网关同一批材料的 high 推理首字实测 8–17 秒，5 秒会稳定失败。
- 失败提示区分：`等待首字超过 25 秒（网络过慢或模型思考过长）`、`网络错误`、
  `网络/网关错误（HTTP …）`、`鉴权失败`、`请求太频繁`、`模型没有返回有效总结（空响应）`；
  失败不提交、不删历史。

解析只认一个 JSON 对象（容忍代码块/尾逗号）；不看 `summary/permanent` 旧字段。
解析失败、空输出、`finish_reason=length`、明显异常（segments 为空但材料很多、
只有“好的”、单条 content 为空、超过 5 条）或关键词超过写死阈值时，发一次
`sidekick/memory/audit.py` 的统一审核：同一个 LLM profile、temperature 0、attempts 1，
输出 `PASS` 或修正后的 JSON/关键词数组；审核失败同样不 commit、不删历史。
关键词只审核一次，不递归。

### 4.3 失败行为

压缩失败**什么都不删**，历史继续涨（41、42…），下一轮自动重试。失败期间 prompt 历史窗口临时放宽到 `history_max + 10` 条（默认最多 50），让新消息不被 40 条上限挤掉；历史本身仍保留在库里，直到总结成功才删这批。连续失败达到 5 次后恢复 `history_max` 上限并开始丢弃最老输入；WebUI 全局告警条在失败 1–4 次时显示黄色，达到 5 次后显示红色，成功后退回正常。压缩失败记在 `brain.summary.error` / `memory.last_summary_error`，不污染这一轮的 `last_error`；错误文本会明确区分首字超时、网络/网关错误、空响应和结构错误。
向量编码失败只让该行留 `vector=NULL`，下次扫描重试，不影响总结和主回复。

## 5. 出口（`sidekick/output/guard.py` + `sidekick/core/text.py`）

### 5.1 两道工序

| 工序 | 做什么 |
|---|---|
| `sanitize` | 清 markdown、emoji、引号、破折号、括号动作描写；按断句点硬截断 |
| `check` | 命中路径/IP/密钥/系统提示词/内部工具名/网址/自曝身份 → **整句拒发**；路径先查原文，再清洗（防止反斜杠被删后绕过） |

**拒发而不是替换**：替换会造出半成品，拒发至少是安静的。
`服务器`/`密钥` 不再裸拦：只有“部署在/运行在/后台/远程服务器”和
“API/访问/加密/配置密钥”这类系统自曝语境才拒发；“游戏服务器/任务密钥”可以正常说。
`guard.extra_patterns` 里的非法正则会去重告警一次，不阻塞其它过滤。

### 5.2 情感标签的白名单

模型可能写标签；出口只放行**当前 TTS preset** 的 `allowed_tags` / `preserve_square_tags`，动作描写删掉。preset 的 `prompt_rules` 负责教它怎么写，`allowed_tags` 负责模型不听话时兜底；Edge 两者都为空，所以不会念标签。保留标签时沿用原开闭括号（ASCII `(laughs)` 不会被改成全角）。

## 6. 声音（`sidekick/output/speaker.py` + `sidekick/output/player.py` + `sidekick/output/display.py` + `sidekick/output/tts/`）

### 6.1 两个开关

```yaml
tts:
  common:
    stream: <bool>        # 厂商原生流式：一次请求边收边播
    segments: <segments>  # 非流式时怎么分句
```

`tts.common.stream=true` 且 preset 支持流式（PCM + raw/SSE）时，整段一次请求、边收边播；
不支持流式的 preset（Edge / Aivis）自动退回 `segments` 逐句合成，功能不受影响。
`stream=false` 时全部按 `segments` 逐句合成；`prefetch` 只在非流式下预取下一句。

### 6.2 两个 wire + 厂商 preset

厂商差异在 `sidekick/config/tts_presets.py` 的数据里；代码只有两个 wire：
`sidekick/output/tts/http.py`（HTTP/SSE/raw）和 `sidekick/output/tts/edge.py`（edge-tts）。
首批 9 家：

| 厂商 | 语言 | 接口 | 流式 | 音频 | 标签 |
|---|---|---|---|---|---|
| Edge | 中/英/日 | edge-tts 库 | 否 | mp3 整段解码 | 无 |
| OpenAI 兼容 | 取决于网关 | `POST {base_url}/audio/speech` | chunked | PCM | 无 |
| 豆包（火山引擎） | 中 | SSE `unified/sse` | SSE | PCM | 无 |
| Fish Audio | 中/英/日 | `POST /v1/tts` | chunked | PCM | `[english]` |
| MiniMax | 中/英/日 | `POST /v1/t2a_v2` | SSE | PCM | `(english)` |
| Cartesia | 多语 | `POST /tts/bytes` | chunked | PCM | 无 |
| ElevenLabs | 多语 | `POST /v1/text-to-speech/{voice}/stream` | chunked | PCM | 无 |
| Aivis Cloud | 日 | `POST /v1/tts/synthesize` | 否 | wav 整段解码 | 无 |
| 小米 MiMo | 中 | `POST /chat/completions` | SSE | PCM | `（中文）` |

- `tts.source` 是 profile 名；profile 里的 `preset` 决定协议，其余字段由 preset 声明。
- 新增同形状厂商：只改 `tts_presets.py` 一段数据；新增协议形状：才加一个 wire 类 +
  `make()` 一条分支，其余不动。
- 只支持 HTTP API 型厂商，不内置 GPT-SoVITS / CosyVoice / piper 等本地推理引擎。
- Aivis 的 wav、Edge 的 mp3 都整段解码，不声明流式；PCM 厂商才能边收边播。

### 6.3 各厂商的坑

- **OpenAI 兼容**：`base_url` 填到 `/v1`；官方 `tts-1` / `gpt-4o-mini-tts` 于 2027-01-06 停用，
  网关填网关支持的模型名。PCM 采样率默认 24000，SiliconFlow 等 44100 网关在字段里改。
  `instructions` 留空不传。
- **豆包**：鉴权是 `X-Api-Key` + `X-Api-Resource-Id`；界面把资源 ID 统一显示为「模型」。
  SSE 每行 `data` 是 base64 PCM。错误可能放在 JSON 的 `code` 字段里而 HTTP 仍是 200，没音频时把响应首段带进错误。
- **Fish**：模型名走**请求头** `model`，不是 body；`reference_id` 为空时整个键删掉，用默认音色；
  REST 返回 PCM，能否逐块吐由实测决定，不渐进时把 preset 的 `stream` 设为 `false`。
- **MiniMax**：国内/海外域名不同（`api.minimaxi.com` / `api.minimax.io`）；
  SSE 的 `data.audio` 是 hex，不是 base64。
- **Cartesia**：Bearer 鉴权 + `Cartesia-Version` 头（当前 `2026-08-14`）；`/tts/bytes` 返回裸 `pcm_s16le`。
- **ElevenLabs**：`xi-api-key` 头；音色 ID 在 path，`output_format=pcm_24000` 在 query。
- **Aivis**：日语专用；`voice` 是 AivisHub 的 `model_uuid`；返回 wav，整段解码、不支持流式。
- **MiMo**：不是 `/audio/speech`，而是 `chat/completions + audio`；`api-key` 头，
  SSE 的 `choices.0.delta.audio.data` 是 base64 PCM。`voiceclone` 模型要传音频样本 base64，
  本轮不做；`voicedesign` 同理。
- **Edge**：免 key、免费兜底；mp3 整段解码，首音比 PCM 厂商慢。

### 6.4 标签语法不能混用

| | 括号 | 内容 | 备注 |
|---|---|---|---|
| MiMo | `（小声）` | 固定中文词表 | |
| Fish S2 | `[whispering]` | 自然语言，preset 白名单 | **`(圆括号)` 是 S1 老语法，S2 会照字念出来** |
| MiniMax | `(laughs)` | 2.8 的感叹词表 | 只对 `speech-2.8-*` 生效 |
| Edge / OpenAI / 豆包 / Cartesia / Aivis | 无 | 无 | prompt 不教标签；出口侧也会清掉 |

**prompt 跟随当前 preset**：通用 persona 不写任何一家的标签语法；preset 的 `prompt_rules`
由组合根注入 `PromptBuilder.build_output_block()`，和 `actions.md` 一样进入输出约束段。

- 没有 `tags` 的 preset：`prompt_rules` / `allowed_tags` / `preserve_square_tags` 全为空。
- Fish：`prompt_rules` 只教英文方括号；`preserve_square_tags` 覆盖 preset 支持的标签；
  `adapt_text()` 把中文圆括号标签翻译成 S2 方括号，未知标签删掉。
- MiniMax：只教 ASCII 圆括号感叹词；`clean_tags` 保留原括号，不会把 `(laughs)` 改成全角。
- MiMo：只教中文圆括号固定词表。

`allowed_tags` / `preserve_square_tags` 仍然保留：prompt 不能保证模型一定听话，而模型输出是
外部输入，出口必须再过滤一次；它们和 `prompt_rules` 一起由 preset 声明，不再是通用默认词表。

本地的 `<ACT>` 是另一套命名空间：在 `reply.talk()` 里先解析/剥离，再交给 provider；
方括号/圆括号原样保留给 provider 的 `adapt_text()`。两边不共用 parser，也不共用词表。

### 6.5 音频路由

TTS 播到**系统默认输出设备**（跟随 Windows「系统 → 声音 → 输出」），直播姬用「系统声音」收，你的真麦走「麦克风」。
两条通道天生分开，**不需要虚拟声卡、不需要 Voicemeeter**。

唯一代价：她和游戏声共用系统音量，压不住游戏。靠 `tts.common.gain` 把振幅拉高一档解决。

**重采样用 `soxr`**（`sidekick/output/tts/base.py`）：24k 的合成结果要播到 48k/44.1k 的设备上。
线性插值下采样没有抗混叠，会有可闻混叠；soxr 一行调用、带滤波、比 scipy 轻。
顺序是先**重采样 → 音量 → 削波**：反过来会把重采样的过冲削平，产生额外谐波。
流式路径（`speaker._say_stream`）与一次性播放（`player._prepare`）用同一个顺序。

**口型跟播放位置，不跟收到的音频**：播放线程每写一块（默认 100 ms）就把这一块交给
`SpeechAnalyzer`，按 50 Hz 的 hop 产出 `mouth` 事件（`level/openness/form/voiced`），
Runtime 再经 stage 转发给桌面/浏览器。分析窗口 40 ms、LPC 共振峰给 `openness + form`，
所以 `/a/`、`/i/`、`/u/` 的嘴形不同，而不是同一条音量上下开合。音频块到达但还没写进
声卡时不产帧，因此流式合成不会让嘴提前演完。

### 6.6 语音出错

| 故障 | 处理 |
|---|---|
| 单句合成失败 | 重试 1 次；还失败就整句放弃，不往下念 |
| 首音前失败/无 TTS | **气泡兜底显示全文**（用 `SayResult.display`，不含厂商 TTS 标签），历史仍记录全文；只记 TTS 失败，不 `mark_failed` |
| 播了一半才失败 | **不补全文**——气泡已开始，用 `finish(upto)` 收尾；历史记录实际 `spoken` |
| 整轮一句没播 | 算故障 → 记一次 `tts` 失败 → 播预录音频（`state/fallback/tts_*.wav`） |
| 被用户打断 | **不算故障**：不道歉、不兜底、不计 `fail_rounds`；气泡停在已说页，历史只记已说部分（§1.1.2） |

历史记录被截断的 `spoken` 时，若末尾没有句末标点，会自动补一个 `…`；下一轮模型能看出
上一句没说完。是否算截断用出口层已过 guard 的显示文本比较，不再拿带 emoji/括号标签的
模型原文比较，避免把“清洗掉表情”误记成“说到一半”。

**HTTP 错误文案**（试听与运行期共用，见 `sidekick/output/tts/http.py`）：

| 状态 | 文案 |
|---|---|
| 401 | 密钥无效：确认复制了完整 Key，且账号已开通该语音服务 |
| 403 | 没有权限：账号未开通该服务，或 Key 被限制 |
| 402 | 余额不足：去厂商控制台充值，或换免费额度模型 |
| 404 | 接口地址不对：检查 Base URL（到 /v1 或根地址为止） |
| 429 | 请求太频繁：稍等再试，或调大 `tts.common.timeout_s` |
| 5xx | 厂商服务端出错：稍后重试 |
| 超时 / 连不上 | 连不上服务：检查网络、代理或 Base URL |

错误里附响应前 200 字，不附请求头；密钥不进日志。

日志与气泡同一条边界：Brain 一返回就先记 `[轮次] 想好：…`，TTS 成功/失败都不影响这条；
失败行另带 `气泡兜底：…` / `想说：…`，避免"说了什么"只存在于声音里。

**TTS 挂了不能用 TTS 念兜底话**——这时候没有合成器可用，只能播提前录好的 wav。
目录约定 `state/fallback/{kind}_NN.wav`，现在还没有录音，所以是「静音 + 日志 + 状态标红」。

**首音驱动气泡**：`Speaker` 在**第一块 PCM 真正写进声卡**时发 `started`，
`Display` 收到才推 `say`；合成慢、网络慢都不会让气泡提前出现。
`TTS 成功`时气泡不早于首块音频；`TTS 失败/缺失`时走同一条 `say/end` 兜底路径。

## 7. 形象层（`sidekick/avatar/` + `overlay/`）

### 7.1 为什么是网页

直播姬能加**浏览器素材**，指向本地地址即可。于是：

- 形象和气泡跑在**直播姬自己的窗口里**，只在直播姬那个屏出现，游戏屏一个像素都不碰
- 直播模式不用透明置顶窗口；桌面模式用 `sidekick/desktop/` 的 Pygame + live2d-py 原生 OpenGL 透明窗，不依赖 Electron，也不依赖 QtWebEngine
- 形象和气泡在同一个画布里，所以「她开口 → 气泡冒出来」天然同步

服务默认在 `stage.host:stage.port`（实际跟随 `stage.host`/`stage.port`），**只推形象事件**；
页面不能让她说话、不能改配置。桌面桌宠可通过 `/ws` 发 `click` 把“摸了摸头/手/身子”
送进 brain 材料，不经过浏览器。
`/ws` 只接受本机 Origin（或非浏览器客户端的空 Origin）：

```
GET /            页面（默认形象由 config.role.id 决定，可用 ?avatar= 临时覆盖）
GET /config.json 当前形象 + capabilities + 气泡布局
GET /models      已发现的形象列表
GET /probe       自检页：WebGL 有没有、背景能不能透明
GET /s/*         前端资源
GET /m/<id>/*    Live2D 模型（含 __avatar.model3.json 自动补全清单）/ 单张图片
POST /control    本机 WebUI 代理的实时预览控制（参数/部件/动作/表情/外观/复位/重载）
                 只接受带 X-DeepSidekick-Control: 1 的 WebUI 服务端代理请求，普通 localhost 页面不能直接控制
WS  /ws          {"t":"say","pages":[...],"cps":<stage.cps>} / page / level / mouth / pose / end
                 mouth 帧：{"t":"mouth","v":level,"open":openness,"form":form,"voiced":bool}
                 pose 帧：{"t":"pose","params":{"ParamAngleX":12.3,...},"ts":秒,"seq":n}（只推绑定参数）
                 桌宠客户端可发 {"t":"click","part":"头|手|身子"} 进入 brain 材料
                 队列满时先丢 level/mouth/pose；控制消息（say/page/end/control）仍满才丢最旧一条，
                 保证最新状态能到达慢客户端
```

### 7.1.1 三套渲染器

WebUI 预览的 Inspector 调整会经 `POST /api/stage/control` 转发到 stage，再通过 `/ws` 的 `control` 事件同步给已连接的浏览器舞台和 Pygame 桌宠；参数/部件在两端都于模型 Update 之后写入，动作/表情即时播放。
`全部复位`会同时清掉 Inspector 覆盖、表达式混音和模型动作，把缩放/位置恢复到页面加载时记录的初始取景快照（不按当前动作重算 alpha 包围盒）；
`重载模型`由预览 iframe、浏览器舞台各自 reload，Pygame 桌宠在**同一个窗口/GL 上下文**里
关闭并重建模型（`_reload_model()`，不退出进程、不销毁窗口）；三个显示面都回到模型初始状态，
不需要分别手动调。
浏览器预览里额外的参数覆盖（Inspector/远程控制/自主驱动 pose）会在
`physics.evaluate` 之前再写一次：`beforeModelUpdate` 位于物理求值之后，
物理输入类参数只在那里写会“改了没反应”；直接变形参数仍保留 Update 后的写入。

三类形象（Live2D / 图片 / Spine）各有宿主，桌面与浏览器各用最合适的运行时：

| 宿主 | Live2D | 图片 | Spine |
|---|---|---|---|
| 直播姬 / 浏览器 | `overlay/app.js` + Cubism Web SDK + PIXI/WebGL | `<img>` | `overlay/spine-player.js` + 官方 spine-webgl（按骨架版本动态选 3.8 / 4.0 / 4.1 / 4.2） |
| Windows 桌面透明窗 | `sidekick/desktop/live2d.py` + live2d-py（Cubism Native SDK 5） | `sidekick/desktop/image.py` | `sidekick/desktop/spine.py` + `sidekick/spine/`（ctypes + `vendor/spine/*.dll`） |

浏览器侧的 Spine 与 Live2D 走同一套舞台：同一个 `/config.json` 的 `kind` 分支、同一套
「内容占满舞台、底部对齐」的取景规则、同一个气泡层、同一个 `/control` 广播；
调试面板入口也一样（右侧栏），只是标签页换成动画/皮肤/外观/诊断。

桌面这一侧只认一个契约：`sidekick/desktop/pet_model.py` 的 `BasePetModel`
（`update/draw/resize/set_scale/set_offset/hit_part/start_motion` 抽象，
`look_at/set_mouth/apply_acts/control_*` 有默认空实现，能力查询读 `motion_groups`/`idle`）。
`Live2DRenderer` / `ImageRenderer` / `SpineRenderer` 都是它的实现，`app.py` 主循环不认识
Cubism、Spine 或 Pygame 的具体类型；加渲染器 = 新增一个实现 + 组合根多一个分支。

三者共用 `AvatarCatalog`、模型扫描、`capabilities` 和 stage 的 `say/page/level/end` 事件；
`actions.md` 与 `<ACT>` 标签对 Live2D 和 Spine 是同一套（见 §7.6），图片形象没有动作能力。
`actions.md` 超过 2000 字时读取截断并标 `truncated`；`motion_profile.actions.<name>.enabled=false`
对内建动作同样生效，不出现在词表里，显式 `<ACT>action=...` 和正文动作词推断都不会补回该动作。
桌面点击通过 `/ws` 的 `click` 进入 brain 材料，命中部位词表也是共用的（头/手/身子）。

**窗口自适应（两个引擎同一口径）**：**窗口去适配形象，而不是形象去挤窗口**。
桌宠窗的宽度不配置，按当前形象的宽高比生成（高度基准 680 px，Live2D 取 canvas 比例、
Spine 取待机动画的真实网格、图片取图片本身的宽高比）；窗口再大也只放大高度，形状不变。
滚轮只改大小、不改形状；「调试 → 外观 → 整体大小」改的是模型自身缩放，两者不叠加。
Live2D 桌面的水平/垂直位置传 `live2d-py` 的归一化 `SetOffset`（直接使用
Inspector 的 `-1..1` 值，不乘窗口像素）；Spine 的 offset 才是像素，由渲染器自己乘窗口尺寸，
且设置后会立即 `_place()` 同步 C 层命中/拖动坐标，避免偏移后点不准。
滚轮顶到工作区上限时记住的是**实际生效**的缩放，不会攒下一段"按了没反应"的隐藏缩放。
Spine 的取景框按「待机动画播一遍的真实网格」算，不用附件包围盒（游戏拆包模型常有大量
隐藏附件，按包围盒会"框很大、人很小"），默认按 88% 取景（留 12% 出血位）、底部贴边、
不裁切。

浏览器舞台没有窗口可调，画布跟着直播姬的素材尺寸走：Live2D 按内容包围盒填到 92% 高度、
底部对齐；Spine 交给官方播放器自动取景（左右留 2%、顶部留 10%、底部贴边）。

**贴图质量**：桌面窗的 Spine 图集用 mipmap + 三线性 + 8× 各向异性，缩小到 1/10 也不闪不脆；
浏览器舞台用官方播放器自带的纹理过滤。放大都受源图分辨率限制（低清图集放大会糊，
是素材问题，不是渲染问题）。

**透明怎么做的**：桌面窗不用颜色键，而是把 DWM 边框扩展到整个客户区
（`DwmExtendFrameIntoClientArea(-1)`），由 DWM 按窗口像素的 alpha 合成到真实桌面：
帧缓冲要带 alpha（`GL_ALPHA_SIZE=8`）、清屏色 `(0,0,0,0)`、模型按预乘 alpha 画，
`pygame.display.flip()` 之后不再有我们自己参与的合成步骤。好处是没有"先合成到黑底、
再整像素抠掉"的软边损失——浅色壁纸下也不会出现一圈黑/白描边。
窗口常驻 `WS_EX_LAYERED`，并用 `SetLayeredWindowAttributes(0, 255, LWA_ALPHA)` 初始化；
这不使用 `UpdateLayeredWindow`，OpenGL 仍走 WGL/DWM 逐像素 alpha 合成。整窗透明度在
提交前把像素整体乘一个系数（`GL_ZERO / GL_SRC_ALPHA` 的全屏 quad）；右键「透明度」是
竖滑块，上 100%、下 20%（再低就看不清了），按住拖动连续调节，菜单开着时先压暗模型再
画菜单——所以拖动时就能看到变化，而菜单本身保持不透明、点得准。

**窗口缩放**：改窗口尺寸走 `pygame._sdl2.video`（pygame 2.6+），不重建 GL 上下文；
如果这个模块不存在，桌面窗**直接启动失败**并提示重装依赖——退回
`pygame.display.set_mode` 会重建上下文，Live2D/Spine 的贴图和缓冲会全部失效，
那比启动失败更难查。

不把 live2d-py 或 Spine 的原生库塞进浏览器，也不让浏览器 SDK 去管原生透明窗：前者不能跑在网页里，
后者拿不到 Windows 的窗口样式和全局鼠标钩子。渲染器是同一模型的不同宿主，不是几份模型配置。

### 7.1.2 Live2D 程序化驱动（桌面与浏览器）

桌面 Live2D 不再依赖 `.motion3.json` 待机：加载后由 `sidekick/motion/` 自省模型参数，关掉 Cubism 的
`SetAutoBreath`/`SetAutoBlink`，也不主动 `StartRandomMotion(idle)`；主循环每帧按
`model.Update(dt) → 引擎 tick → 所有权过滤 → 写参数 → Draw` 执行。待机漂移、眨眼、呼吸、虚拟注视、
全身姿态锚点和说话伴随动作全部由归一化语义通道产生，再在最后一层映射到模型真实参数。

- **单一姿态弹簧**：`compose()` 只输出目标姿态；`MotionEngine` 把 `head_*`、`body_*`、
  `lean_y`、`arm_*`、`hand_*`、`shoulder_*`、`leg_*`、`hip`、`brow_*`、`eye_x/y` 统一送进
  一个 `SpringBank`，再写模型。头部弹簧（约 1.5 Hz、ζ≈0.60）比躯干（约 0.88 Hz、ζ≈0.65）快，
  所以转头时头先到、身体慢半拍跟过去并带一点过冲；手臂/手腕再按肩→大臂→小臂→手的顺序滞后。
  `eye_l_open/r_open`、`mouth_open/form`、`breath` 走各自的状态机，不经过这个慢弹簧
  （否则眨不闭眼、口型粘连）。
- **姿态锚点**：`sidekick/motion/posture.py` 的 `PostureAnchor` 维护 7 个全身静息姿态
  （居中放松、前倾专注、左右歪头倾听、左右慵懒侧靠、侧身看弹幕）。倾听/说话/待机使用不同的
  条件权重，每 1.4–5.2 s 切换一次，禁止连续同一状态，幅度带 0.85–1.15 随机扰动。姿态里刻意让
  `head_z` 与 `body_z` 反号（Contrapposto），避免“脖子折了”的歪头。情绪自带的
  `eye_squint` 会写入模型独立的眼眯参数（有该参数时才生效）。胸部的呼吸值经过
  约 0.2 s 的一阶滞后再写 `chest_y/chest_x`，所以吸气时胸腔比躯干晚半拍，不是整块刚体。
- **说话微表情与回眸**：说话时按短语能量给眼角加一点 `eye_l_smile/eye_r_smile`
  （悲伤/生气不加强笑），思考/困惑时左右眉一高一低；说完一句、停止说话时，注视点会
  回到镜头停留 0.4–0.8 s 再继续看游戏/弹幕。
- **双频带语音伴随**：`ProsodyTracker` 从 50 Hz `SpeechFrame` 提取慢速短语包络
  `env_phrase`、有符号音节重音 `a_beat`（fast/mid 包络差）和只在说话时推进的说话相位 `phi`。
  说话时头部、躯干、肩膀、双手按李萨如相位错相摆动；静音后短语包络归零、相位冻结，
  不会继续点头，也不会在下句开口时跳变。重音信号直接进弹簧，不再叠加一阶低通/每帧 slew——
  二阶弹簧本身就是 -40 dB/decade 的低通，额外滤波只会把动作压平。
- **动作编舞**：23 个语义动作（另有 4 个只切换离散状态的 `穿长裙/穿短裙/变Q版/正常比例`）使用
  `Anticipation（反向蓄力）→ 带 8% 过冲的爆发 → 呼吸保持 → 欠阻尼释放` 四段包络；多关节动作的 `loops` 带通道级相位差（挥手时肩 0、大臂 -0.45、
  小臂 -1.15、手腕 -1.80 rad），所以不是一根木棍在肩关节上转。缺失手臂/腿时按
  `sidekick/motion/introspect.py` 的补偿矩阵折进躯干/头部，而不是静默丢掉；只有一侧手臂的
  模型会把动作自动镜像到存在的那一侧。`wave` 默认用角色右手（屏幕左，`my-model` 的
  `Param62`），`stretch` 改成弯肘上举且只在冷场 ≥35 s、距上次 ≥90 s 时进入待机池。
  `compose()` 在弹簧前还会执行剪影守护：大臂抬起时小臂不得反向绷直，非双手动作不允许
  双臂对称平举；手放胸口/拿狗尾草这类深弯肘动作会压住上臂和手腕（肘越弯，上臂越贴近
  躯干），避免整条手臂拧成麻花。显式动作的包络强度还会平滑压低 `posture`、`idle` 和
  说话韵律（`action ducking`），动作期间不会出现“往左靠的姿态”和“鞠躬”互相抵消。
- **自动表演**：说话期间没有显式动作时，高能重音（`a_beat`）或持续说话会按当前情绪触发
  0.55–0.75 强度的自动微手势；空闲微动作间隔 4.5–9.5 s、75% 概率，候选含歪头、移开视线、
  点头、耸肩、靠、思考，有尾巴的模型再加摇尾巴。`stretch` 不再属于高频候选，只在冷场
  ≥35 s 且距上次 ≥90 s 时出现。腿/脚/胯是很多游戏模型最灵活的部分，`compose()` 用约
  0.13 Hz 的慢速重心偏移驱动左右腿反相承重：重心一侧的腿伸直，另一侧膝盖微屈，
  脚踝按大腿/膝盖角度反向踩地，脚掌不跟着腿在空中画圆。`foot_swing` 平时只有 ≤0.05
  的幅度，开心/兴奋或 `bounce/cheer/sway_hip/leg_shift` 期间才放开。`leg_shift`
  （换重心/活动腿）进入随机待机池，`kick` 仍是显式动作，不会在待机里高频踢腿。
- **物理输出与级联参数**：`read_physics_graph()` 解析 `.physics3.json` 的输入/输出参数集合。
  头发/未知装饰的
  物理输出参数不绑定，避免把物理摆锤锁死；但 `ParamAngle*`、`ParamBodyAngle*`、手臂/腿，
  以及胸部/裙子/袖子/飘带/尾巴这些**已知次级变形通道**，拆包模型常把它们本身声明成物理输出，
  完全不写会让上半身和衣服失去大半形变，因此 `DRIVABLE_PHYSICS_CHANNELS` 允许显式驱动它们
  （写入发生在 Update 之后；桌面宿主对次级叶结点用物理值叠加，不覆盖原生摆锤）。同语义的级联参数（`AngleX`、`ParamBodyAngleZ1/2`、
  `JawOpen`、`RHand2`、`ChestX2/3`、`SkirtX2..` 等）进入 `ModelProfile.followers`，
  用各自的 `min/max/default/kind` 独立换算后一起写，不直接复制主参数 raw 值。
  尾巴/裙摆/胸/袖/飘带/`lean_y` 这类链式通道最多保留 8 个 follower，按名字里的数字序号
  排序；写入时用上一帧到这一帧的速度差给后段一个相位滞后，形成从根到尾的行波，而不是
  整条尾巴同幅硬摆。物理输入参数（`physics.inputs`）在桌面宿主写普通参数时同时写
  `SetSaveParamByIndex`，让下一次 `Update()` 的 `LoadParameters()` 在物理求值前先读到；
  **同时属于 `physics.outputs` 的级联中间节点不再写 saved**，否则会把物理输出锁进
  `savedParameters`，造成跨帧正反馈。
  桌面传给 `Model.Update` 的 dt 做 EMA 平滑（夹在 1/75–1/45 s），物理输出（尾巴等）
  和 head 角度在 `Draw` 前做二阶差分单帧毛刺限幅；限幅后仍记录**未过滤的原始值和速度**，
  避免把 clip 结果当成下一帧起点而持续锁死，正常摆动不会累积改写。Inspector 当前手动
  覆盖的参数不参与限幅，改滑块的大跳变不会被当成毛刺削掉。
  浏览器宿主则在包装后的 `physics.evaluate` 之前写 Inspector/远程/pose 参数。次级物理叶结点在桌面宿主采用 `phys_now + (raw - default) * 0.80`
  的叠加写入：Cubism 自己的摆锤保留，引擎的大幅动作再叠上去；浏览器宿主把同一批
  叶结点的 raw 值换算成相对 default 的 `add` 字段随 `pose` 发送。`overlay/app.js`
  没有 `afterMotionUpdate` 钩子，因此包装 `physics.evaluate`：求值前先写基础姿态，
  让同帧物理读到新的头/身；求值后再写一次基础姿态，并读当前物理值加
  `delta * 0.80`。桌面窗和浏览器舞台的胸/裙/尾巴叠加策略因此一致。
- 模型自己的 motion/expression 仍然可播；播放时它写过的参数由 `MotionOwnership` 按参数 ID 暂让，
  结束后从模型最后值平滑交接回引擎，默认 320 ms，可由 `motion_policy.ownership.crossfade_ms`
  调整。桌面端从模型读最后值；浏览器端在 `overlay/app.js` 用
  `coreModel.getParameterValueById()` 取真实当前值做 320 ms smoothstep，不用陈旧的引擎值。
  `mouth_open` 及其 followers 在说话时始终归口型；`motion_policy.model_motions` 里 `enabled: false`
  的模型动作不会被标签/菜单自动播放。
- 情绪标签除驱动程序化情绪层外，还会按 `motion_profile.expressions`（情绪 → expression 名）
  调用表情混音器；没有映射或名字不存在时只走程序化层。表情不再走 SDK 的单表情
  `SetExpression/ResetExpression`：`sidekick/motion/expressions.py` 和 `overlay/app.js` 各有一层
  混音器，按 `.exp3.json` 的 `Add/Multiply/Overwrite` 叠加参数，每个表情独立
  FadeIn/保持 6 秒/FadeOut，所以“脸红 + 爱心眼”可以同时存在；说话时嘴部参数及其
  followers 仍归口型。
  浏览器宿主对 `emotion` 还会向页面补发 `control(op=expression, name=...)`，否则后端
  让位后页面不播，表情会空 6 秒。显式 `motion=idle` 会让混音器淡出全部表情，避免
  “前倾/爱心眼”一直挂在脸上。关闭自主驱动时走 SDK `SetExpression`，6 秒后同样
  `ResetExpression` 清残留表情。
- 非标准命名/数字 ID 的参数先从 `cdi3` 显示名映射，再回退到别名表：`R大臂z`/`L大臂z` →
  `arm_r/arm_l`，`R小臂Z`/`L小臂Z` → `arm_*_bend`，`R手腕Z`/`L手腕Z` → `hand_*`，
  `R食指` → `finger_r`，`大臂透视` → `arm_*_persp`。这样 `my-model` 的
  `Param36/41/42/43/62/60/61` 等“数字参数”会覆盖物理输出 `RArm`/`RForearm`，不会被
  误判成无效绑定；没有显示名时才回退到旧别名。
  **VTube 证据**：`sidekick/motion/vtube.py` 只读模型目录里的 `.vtube.json`。作者写的
  `ParameterSettings` 提供 `Input → OutputLive2D`、真实工作区间、输入/输出反相和
  `UseBreathing`，`Hotkeys` 提供作者命名的表情/动作与 `IdleAnimation`。反相换算成
  `ParamSpec.polarity`（写入前取反），比 `.moc3` 窄的区间换算成
  `effective_min/effective_max`（先裁到 `.moc3` 范围，默认值始终保留在区间内）；
  `Hotkeys` 只进审计和生成
  证据，不改变模型文件。没有该文件、JSON 损坏或输出参数不在当前模型里时按普通词法
  自省处理。
  **证据图**：绑定不再只看一条 if-else。`introspect()` 为每个候选累加
  `manual/profile`、`.vtube`、`cdi3`、名称词表、motion 活动、几何探针六类证据，写进
  `ParamSpec.confidence/evidence`；置信度低于 0.55 不绑定。纯数字 ID 没有 cdi3/
  VTube/探针/动作证据时保持 `unmapped`，不靠相关性猜语义。审计 dossier 的
  `params[]` 带 `polarity/effective_*/confidence/evidence`，`unmapped.rows` 带高价值
  未映射参数的名称、量程和探针 `(cx, cy, span_ratio)`。
  **几何探针**：`sidekick/motion/probe.py` 在审计子进程/CLI 里用 1×1 隐藏
  `pygame.OPENGL | pygame.HIDDEN` 窗口刷新 Cubism 网格；桌面加载期复用已有 GL
  上下文，只探左右同名手臂、眼部和头部参数（后者用于鼠标注视原点）。`live2d-py` 的
  `Model.Update()` 只跑动作/呼吸/物理，真正调用 `csmUpdateModel` 的是
  `Model.Draw()`；探针因此按 `SetParamById → Draw → GetDrawableVertices` 逐参数
  测顶点差分，不需要 cdi3，也不修改模型。每个参数报告 `cx`（屏幕左右质心，
  `-1` 左 / `+1` 右）、`cy`（0 脚底 / 1 头顶）、`span_ratio`（最大位移占主体
  包围盒）、`q_ratio`（25% 行程位移占满幅）、`moved_drawables` 和 `screen_side`；
  `.physics3` 的输入源如果不动顶点，额外带 `virtual_input=True`，用来区分
  “虚拟物理输入”和真正的废参数。它只测顶点，不读取 Drawable 透明度/渲染顺序；
  某些只改透明度或贴图的手型/换装开关会表现为 `active_vertices=False`，探针不会
  伪造图层信息。
  审计 dossier 增加 `probe` 段与顶层 `screen_side`；同名 `大臂透视` 不再按 cdi3
  顺序猜边，而是和 `arm_l`/`arm_r` 的质心配对。`q_ratio < 0.12` 且
  `span_ratio >= 0.05` 的连续参数由 `ParamSpec.gamma` 把小幅输入推过前段死区；
  `gamma < 1` 在 `|v| < 0.08` 内改为线性过零，避免 `|v|^gamma` 在 0 处导数无穷大
  导致头部平滑过中线时单帧角速度暴涨；`|v| >= 0.08` 仍走原幂函数。`gamma` 只由
  审计/几何测量写入，默认 1.0。无显示环境、缺少 pygame 或 GL
  上下文创建失败时，审计回退到词法自省，并在 `probe.error` 里写明原因。
  审计只探已绑定参数和已识别状态参数（不是模型全部参数），避免几百个参数
  把子进程拖过超时。
  `Lean Y`/`Lean Y 2`/`Lean Y 3`/`Lean Input` → `lean_y`（主参数 + 同级 follower），
  让前倾不再只靠 `ParamBodyAngleY` 的极性和量程。腿部按关节拆分：
  `ParamLeg*1Z/2Z/3Z` → `leg_*` / `knee_*` / `ankle_*`，
  `ParamLeg*1Y/2Y/3Y` → `leg_*_y` / `knee_*_y` / `foot_*_y`，
  `ParamLeg*1X` → `leg_*_x`，`ParamFootLX/RX` → `foot_l/foot_r`，
  `ParamLegLF` → `foot_swing`（两只脚一起前后摆）。左侧没有 `LegL1X` 时只缺少
  `leg_l_x`，不影响其他关节。`kick` 同时驱动髋、膝、踝、脚掌和脚踝侧摆，
  不再只写一个腿参数。
  识别不绑定模型 ID：通用 `Thigh/Knee/LowerLeg/Ankle/Foot/Toe`（含
  `LThigh/RKnee`）和 cdi3 的 `大腿/小腿/脚腕/脚掌/脚尖` 都走同一套词表；
  `LegR1Z/2Z/3Z` 只是常见的数字编号写法，按 1=髋、2=膝、3=踝解释，若某模型
  编号含义不同，应在审计 warning 里人工确认后再加别名。三关节都只绑定一个参数且
  探针 `cy` 差足够大时，`introspect()` 按“髋高于膝、膝高于踝”重排；探针的左右质心
  与 `_l/_r` 命名相反时只降置信度并记 warning，不静默改名。
  `models/my-model` 这类把物理输入拆成 `ParamAngleX/Y/Z`（物理输入角度）+
  `ParamAngleX4/X5`、`Y4/Y5`、`Z4/Z5`（物理输入身体 X/XX/Y/YY/Z/ZZ）的模型，
  身体副本显式映射到 `body_x/y/z` 的 follower；`ParamBodyAngleXX` 同理，避免被
  `canonical_base` 去掉数字后误绑回头部。
  `ParamBodyBreechX` → `hip`，`ParamBreastX/Y` → `chest_x/chest_y`，
  `ParamSkirtL/R/Side*` → `skirt_x`，`ParamTailX*` → `tail`，
  `ParamHairBack/Front/Braid*` → `hair_back/hair_front/hair_side`；
  `ParamLegR1X` → `leg_r` 的 follower，`ParamLegLF` → `foot_l` 的 follower。
  胸部/裙子/尾巴如果是 physics 输出，桌面宿主仍用“物理当前值 + 引擎偏移”的
  叠加写入，不覆盖原生摆锤；头发输出不绑定，保持纯物理，只让已绑定的头发通道
  跟随头/躯干并参与待机噪声。
  `leg_shift` 作为轻量腿部动作进入待机候选，和连续的腿/脚重心偏移一起用，
  避免只有 `kick` 才能看到腿动。
  `动画双手开关` → `arm_gate`、
  `竖手指大臂无缝用` → `hand_gate`，抬手/竖指时打开图层/无缝开关，降低手留在
  头发或身体后层的概率；没有这些开关的模型自动忽略。
- **离散状态**：从 `cdi3` 显示名自动发现换装/体型/手型开关（`长短裙切换`、`大小变`、
  `胸口衣服`、`抚胸`、`竖食指`、`狗尾草`），生成 `StateSpec`。持久状态跨轮保持
  （`穿长裙` 后不会 2 秒弹回短裙）；定时手型状态在保持时间结束后释放；同互斥组
  （`hand_style`）激活一个会关掉其余。状态参数在 `to_parameters()` 之后单独写回；
  **持久状态即使关闭也每帧写 inactive 值**（Cubism 的 `LoadParameters()` 会带回上一帧
  写过的值），所以 `变Q版 → 正常比例`、`穿长裙 → 穿短裙` 不会只生效几秒后弹回。
  `恢复默认体型` 这类模型 expression 在存在 `chibi_mode` 时会被改写成持久动作
  `normal_body`。
- **次级变形通道**：胸部（`胸X*`/`胸Y*`）、裙子（`裙X*`/`裙Y*`、层级）、袖子
  （`左/右袖子X/Y`）、飘带（`左/右飘带X/Y`）、尾巴（`[n]尾巴`）和手部贴图切换
  （`狗尾草`/`抚胸`/`竖食指`）也从显示名映射成独立通道。胸部/裙子/袖子/飘带/尾巴跟随
  躯干、呼吸、说话韵律和胯部运动；`hand_style_point`/`hand_style_chest`/`hand_style_grass`
  分别由 `point`/`sob`/`bounce`/`hand_chest` 动作触发表情手。
  同一通道的多个物理分身进入 `followers` 一起写；待机尾巴还有 0.35 Hz 的低幅自发摆动。
- 鼠标不再走 Cubism `Drag`：先经 `gaze.pointer_target()` 按眼部原点校准，校准后的指针作为
  `Context.pointer`，由注视控制器连续跟随；没有 `pointer_origin` 时回退窗口坐标归一化。
  有几何探针时，`ModelProfile.pointer_origin` 取眼部通道的 `(cx, cy)`，鼠标贴在脸上时不会偏到肚子。
  `follow_mouse` 关闭时指针清空，
  回到虚拟兴趣点。
- 桌面窗的 `update(dt)` 使用真实帧间隔并 clamp 到 0.1 s；窗口暂停/拖动不会把弹簧甩飞。
- 运行时当前使用模型自省得到的默认绑定。`stage.autonomy.enabled: false` 时宿主换成空对象，
  恢复 SDK 眨眼与模型 idle motion，鼠标回到 Cubism `Drag`；该开关重启 runtime 生效。
  模型自带 idle motion 时不再同时开 SDK 自动呼吸：`CubismBreath` 会在 idle 循环边界向
  `ParamAngleX/Y/Z` 漏出一帧正弦偏移，造成整窗抽动；只有没有 idle motion 的模型才用
  自动呼吸始终保留；idle 循环边界可能漏出一帧角度，由 `Draw` 前的 head_x/y/z 单帧
  毛刺保护兜底，而不是关闭整个呼吸。SDK `Drag` 只覆盖标准 `ParamAngle*`/`ParamBodyAngleX`，
  关闭自主驱动时还会按 `profile.by_channel` 补写 head/body/eye 通道，让 `my-model` 这类自定义
  上半身参数也能跟随鼠标。
- **两个独立开关**：`stage.autonomy.enabled` 只管程序化姿态/口型/自动动作；`stage.actions.enabled`
  只管 `<ACT>` 动作规则（`actions.md` 的注入与解析）。两者互不联动：可以只开自主驱动、
  只开动作规则，或都开；都需重启 runtime。角色页的「动作规则」「自主驱动」面板各有一个
  开关，写入全局 `config.yaml`。
- **手动动作优先**：右键菜单/Inspector 的模型 motion 不受 `motion_policy.model_motions`
  的自动播放开关限制；`enabled: false` 只约束自主驱动的自动资产播放，手动选择始终可播。
- **动态能力卡**：`AvatarActions` 绑定运行时的 `ModelProfile` 后，按真实存在的通道/状态
  生成 prompt 能力说明（尾巴、前倾、扭腰、手放胸口、竖食指、长裙、Q 版）；模型没有的
  能力不会出现在说明里，也不会让 LLM 把 `action=长裙` 当合法标签。`action=` 的精确别名
  失败后还有词根兜底（`看旁边→look_away`、`晃晃尾巴→wag_tail`、`扭扭腰→sway_hip`），
  LLM 忘写标签时正文里的明确动作词也能补一个 intent；正文出现“没有/不能”等否定则不补。
- **审计缓存**：审计结果按 `model3`、`moc3` 及模型目录内所有 `.json`（exp3/motion3/
  physics3/pose3/cdi3/vtube 等）和 `.moc3` 的 `mtime_ns + size` 存到
  `state/audit_cache/<指纹>.json`；key 带审计格式版本，模型或资产变了就重跑，不会继续用旧
  dossier。需要强制重审时用 `validate --no-cache`。
- **浏览器宿主**：`stage.mode=live` 且自主驱动开启时，runtime 用审计子进程拿模型事实，
  在 runtime 里跑同一引擎，以 60 Hz 推 `pose`；Pixi 只在 `beforeModelUpdate` 按参数 ID 写，
  不重复自省、不跑第二套数学。`say`/`page` 的资产动作由 runtime 先按参数所有权让位。
  浏览器在自主驱动开启时调用 `motionManager.stopAllMotions()` 关掉模型自带 idle motion，
  并把 PIXI 的 `eyeBlink.updateParameters`/`breath.updateParameters` 置空，避免 SDK 的
  眨眼/呼吸/idle 和 pose 抢同一批参数；`update` 不是这两个对象的实际更新入口。此时说话
  也不再走浏览器随机表情/动作回退，动作只来自 runtime 的 pose/资产事件，避免“系统驱动 +
  随机回退”两套动作，也避免模型自带的“圈圈眼/加载”一类 idle 片段随机出现。
  浏览器参数读写统一走 `string -> index` 表再调用 `setParameterValueByIndex`/
  `getParameterValueByIndex`；Cubism 的 `CubismId` 参数接口不能直接传字符串，否则会静默
  新建“不存在的参数”并丢弃写入。
  `pose` 里的浮点数保留 3 位小数。
- **舞台页自动恢复**：已打开的直播姬页面每 5 秒拉一次 `/config.json`，模型/入口/布局或
  `autonomy.enabled/active` 变化会 reload；如果舞台页比 runtime 先打开，第一次拿到非空配置时
  也会重新初始化，不需要手动刷新浏览器素材。
- **预览页不连 WS**：WebUI iframe 的预览没有 `pose`，所以仍走模型 idle motion；这是明确限制，
  不是“预览和直播不一致”的 bug。`/config.json` 会带 `autonomy.enabled`，预览据此不关 idle。
- 2026-11-16 本机 4–6 秒 smoke（`my-model`，含 6 段尾巴/56 个 followers/2 个
  图层门控）约 0.48–0.53 ms/帧、写回 101–103 个参数；更小的模型约 0.2–0.3 ms/帧。
  全部在模型范围内；这是本机测量，不是跨机器契约。
- 口型不再用 10 Hz RMS：`mouth` 帧按播放位置以 50 Hz 到达，桌面用 `SpeechFrame` 喂给引擎；
  `level` 事件保留给诊断/旧协议，不直接决定嘴型。浏览器 `beforeModelUpdate` 写
  `lipSync` 参数时使用同一组 `mouth` 帧，静音 200 ms 后自动闭嘴。

### 7.2 形象目录：`models/` 只放模型素材

**模型的类型不写死名字，也没有配置路径、没有清单文件**。服务端固定扫描
`models/`：含 `*.model3.json` 的文件夹是 Live2D，含同名 `.atlas` + `.skel`/`.json`
的文件夹是 Spine，`models/` 根目录或 `models/images/` 下的单张 `.png` / `.jpg` /
`.jpeg` / `.webp` / `.bmp` / `.gif` / `.svg` 是图片形象：

```text
models/
  my-model/
    my-model.model3.json
    ...
  我的形象/
    我的形象.model3.json
    Animation/           # model3 没引用也会自动扫描
    Exp3/
  hero/                  # Spine：一个形象一个文件夹
    hero.skel            # 二进制骨架（或 hero.json）
    hero.atlas           # 必须与骨架同名
    hero.png             # 图集页图，按 atlas 的 page 段取，可能不止一张
  images/deepseek.svg    # 默认兜底形象：和用户自己的图片完全同等对待
  cat.png                # 单张图片形象（放 images/ 或根目录都行）
```

- **默认兜底形象就是一张普通图片**（`models/images/deepseek.svg`，跟仓库走）。
  没有别的模型时它被正常扫描出来、正常选中，没有任何内置特例；
  扫描顺序是 Live2D → Spine → 图片，`role.id` 匹配不上任何形象时取第一套可用的。
- **不可用的模型不进下拉**：体检不过（缺 moc3/纹理、Spine 版本不支持、图集页缺失、
  骨架里有会让原生层崩溃的 curve 值……）的形象，WebUI 的角色下拉和自动选中都会跳过它，
  并在「角色设定」页的角色选择框下方用黄字逐条列出「文件夹名（原因）」；
  一套能用的都没有时才回退到全量列表，避免用户看不到"该修哪个"。
- **单张图片只认两处**：`models/` 根目录和 `models/images/`；放在别的子目录里不算形象
  （免得把模型内部纹理当成独立形象）。透明背景的 alpha 原样保留，gif 只取第一帧。
- **Spine 支持 3.8 / 4.0 / 4.1 / 4.2**，各带一份 `vendor/spine/spine*.dll`
  （3.5/3.6 的许可不允许分发，3.7/4.3 未验证，一律按"不支持"处理并在扫描阶段标 broken）。
- **预乘与否优先信 atlas 里的 `pma:` 声明**（4.x 导出会写）；没有声明才按像素比例兜底判
  （预乘的不变式是 RGB ≤ A，真正非预乘的图半透明像素几乎全违例）。判错会让半透明边缘发黑，
  表现成脸上、腿上一圈"模型线"。
- **Spine 的动画名按需读**：`.json` 骨架在扫描时顺手读顶层 `animations`；
  `.skel` 是二进制，等这个形象被选中或被查询时才起一次子进程问原生库
  （`sidekick/spine/names.py`），结果按「路径 + mtime + 大小」在进程内记忆。
  扫描本身只回答"有哪些模型、能不能加载"，不会把整批模型读进内存。
- **模型 id = 内容指纹**：Live2D 取 `moc3` 的 SHA1 前 16 位（没有 moc3 时取
  `model3.json`），Spine 取骨架文件的 SHA1 前 16 位，图片取文件内容的 SHA1 前 16 位
  （默认那张图也一样）。它用于 `/m/<id>/…` 的渲染地址和缓存，跟文件夹名无关。
- **角色 id 的初始值 = 模型文件夹名 / 图片文件名（去扩展名）**，但 `role.id` 与两个
  文件夹名都解耦：绑定关系写在 `persona/roles/<role.id>/profile.yaml` 的 `model` 字段。
  选中模型并保存时把 `role.id` 写进 `config.yaml`；之后模型文件夹、角色目录改不改名，
  都按 `model` 字段重新找，不靠目录名猜。模型文件夹改名后旧 profile 的 `model` 匹配不到，
  这个形象按新角色处理；角色目录改名后 `model` 还在，绑定仍然有效。
  内容完全相同的两份模型仍各自有独立的 `avatar.id`；不同内容的同名文件夹
  用内容指纹前 4 位消歧（`dup-a1b2`），仍冲突才加 `-2`，删模型重扫不会因序号回退串台。
  `profile.yaml` 同时记录 `model_digest`；同名模型删掉一份后，幸存者不会继承另一份
  的角色目录（扫描时发现 `model_digest` 不匹配就改用带指纹的目录）。
  显示名（`profile.yaml` 的 `name`）只影响下拉和页面显示，不参与任何目录寻址；
  下拉只显示显示名，不再拼 `role.id`。
- **旧目录兼容**：旧版本用内容指纹做 `persona/roles/<指纹>/`。扫描时如果新目录不存在、
  旧指纹目录存在，就先读旧目录；第一次保存角色设定时把它迁到 `role.id` 名下，
  并在同一份 `profile.yaml` 里补上 `model` 绑定。配置里仍是旧指纹时按 `avatar.id`
  找到对应模型，保存后改成新的 `role.id`。
- 配置里默认的 `role.id: deepseek` 对应默认图片 `models/images/deepseek.svg` 的文件名；
  没有这套图片时按扫描顺序回退到第一套可用形象（见 §7.2.2）。
- 图片形象没有动作/表情/口型/部件，但气泡、WS 事件和桌面窗照常工作；
  它也可以有角色设定（同一个 `persona/roles/<id>/`）。
- **图片的桌面渲染**（`sidekick/desktop/image.py`）：解码交给 SDL_image，透明背景的
  alpha 原样保留（jpg/bmp 没有 alpha 通道，就按整块不透明处理；gif 只取第一帧）。
  图片等比缩到窗口里贴底居中，窗口按图片比例生成，所以不会被拉伸也不会留边；
  桌面和浏览器用的是同一张文件，两边颜色一致。SVG 由 SDL_image 里的 nanosvg 光栅化，
  那颗库只认标签属性，所以这里补两件事：把 `<style>` 里的类/id 规则摊成行内属性
  （Illustrator / Figma 导出的 `fill` 全写在类里，不摊平就是一片黑），再按窗口尺寸
  包一层 `scale()` 光栅化（它不认 `width`/`height`，只会放大画布、图形原地不动）。
  解不开的图片不会静默变空白：原因写进 notice 报到 `/status`。
- 「角色设定」页有「重新扫描模型目录」；运行中把模型文件夹或图片放进 `models/`
  后点一下，新角色会立刻加进下拉，不用重启。损坏的模型同一次扫描就会黄字列出来，
  不用再去控制台跑扫描命令。
- 当前角色由 `config.yaml` 的 `role.id` 决定；运行中的 runtime 在启动时钉住，
  **下次启动生效**（见 §7.2.2）。
- 缺 `Motions` / `Expressions` 引用时，服务端从 `motions/`、`Animation/`、`Exp3/`
  自动补一份虚拟 model3，不改原文件；缺 `EyeBlink` 组时补 `ParamEyeLOpen/ParamEyeROpen`
  （引擎的 `getEyeBlinkParameters()` 只读 Groups，不补就不眨眼）。
  `LipSync` 组**不补**：Cubism 默认就认 `ParamMouthOpenY`、前端也兜了一层，
  补进 model3 只是让合成清单多一段假数据；它仍作为能力清单上报（prompt/Inspector 要看）。
- **口型是可选的**：模型没有 `ParamMouthOpenY`（或写不进去）时只关口型，动作/表情/气泡/桌宠
  全部照常；桌面窗把原因写进 `notice` 报到 `/status`，WebUI 顶部用黄色提示显示。
  加载时会试写一次把结论定下来，之后每帧不再用 `try` 兜——真出错就该暴露。
  这条提示通道是通用的：图片打不开也走同一处。
- 模型资产用 `<ACT>motion=组名</ACT>` / `<ACT>expression=表情名</ACT>`；组名/表情名仍来自
  `Motions`/`Expressions`，想让词表变中文就在 model3 里写中文。没有清单文件覆盖这些。
- 语义动作（挥手/点头等）由程序化引擎按参数能力生成，不需要模型自带 motion；
  模型没有对应肢体时按缺失矩阵降级。`motion=` 和 `expression=` 都不写时不会误播资产。
- `?avatar=<角色 id / 模型文件夹名 / 内容指纹>` 可临时切模型或图片（页面会去 `/models` 查入口）。

仓库里不带模型文件，只有说明和默认那张图（`models/images/deepseek.svg`）。
`models/` 在 git 里只有 `README.md` 和这张图：一套 Live2D 通常 30~100 MB，
而且带第三方授权，所以不入库。本机放进去的模型/图片照常被扫描到；
换台机器要先拷过去。真要提交某一套：`git add -f models/<名字>`。

模型文件夹或单张图片直接复制到 `models/`（图片也可以放 `models/images/`）即可，
扫描是按目录/文件名来的，不需要改配置。

### 7.2.1 直播 / 桌面两种模式

```yaml
stage:
  mode: <stage.mode>  # live | desktop
  autonomy:
    enabled: <stage.autonomy.enabled>  # 程序化姿态/口型/自动动作
  actions:
    enabled: <stage.actions.enabled>   # <ACT> 动作规则；与 autonomy 独立
```

桌面窗的尺寸不配置：窗口按当前形象的宽高比生成（高度基准 680 px），滚轮只改大小、
不改形状。见 §7.1.1「窗口自适应」。

| mode | HTTP stage（直播姬浏览器素材） | 桌面透明窗 |
|---|---|---|
| `live` | 起 | 不起 |
| `desktop` | 起 | 起（含右键菜单这个桌面调试入口） |

- `live`：直播姬「浏览器」素材指向 `http://<stage.host>:<stage.port>/`
- `desktop`：runtime 启动本地 stage server 后拉起 `sidekick/desktop/` 的 Pygame 透明置顶窗，用 live2d-py 原生渲染

两种模式都只有 Python 一份 TTS，不会重复出声。

桌面依赖随 `requirements.txt` 安装，不再需要 Node/npm：

```powershell
.venv\Scripts\python -m pip install -r requirements.txt
```

切 desktop 模式不需要命令行开关：WebUI「角色设定」页的「形象层」里把 `stage.mode` 设成
`desktop`，重启 runtime 就换过来（写回 `config.yaml`，跟着配置走）。
桌宠窗口常驻 `WS_EX_LAYERED | WS_EX_NOACTIVATE`，初始化时调用
`SetLayeredWindowAttributes(0, 255, LWA_ALPHA)`；空白区域的跨进程穿透由
`WS_EX_LAYERED | WS_EX_TRANSPARENT` 负责，`WM_NCHITTEST` 不再调用模型、也不再返回
`HTTRANSPARENT`。主循环每帧用 `GetCursorPos` + `ScreenToClient` + `model.hit_part()`
判断光标：进入模型立即摘掉穿透位，离开模型/移出窗口后延迟 120ms 才挂回穿透位；
切换只改 `GWL_EXSTYLE`，不再调用 `SWP_FRAMECHANGED`，且放在 `pygame.display.flip()`
之后执行，避开 DWM 采样窗口表面的时机。菜单打开或拖动时强制整窗可点。
`WM_ERASEBKGND` 返回 1；`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`，点击桌宠不抢前台焦点。
Pygame 事件里的 `_effective_hit_part()` 仍负责过滤模型/空白，保证点击不会被误当成摸头。
鼠标跟随不依赖 `pygame.MOUSEMOTION`（穿透态会断流）：主循环每帧用
`GetCursorPos + ScreenToClient` 更新 pointer；自主驱动关闭时直接写
eye/head/body，不再调用 Cubism `Drag`，避免头身与透传的 pointer 两套来源打架。
关闭跟随后目标值平滑回 0，头/身/眼不会停在上一次鼠标位置；回到 0 后立即停写，
把待机角度交还模型 idle。
按住角色可拖动窗口；菜单开着时点在窗口外，用全局按键状态兜底关闭。
DPI 感知在 SDL 建窗之前声明；恢复位置时先按保存坐标所在副屏的工作区算窗口尺寸。
右键菜单可调透明度、置顶、鼠标跟随、左键穿透、动作和退出；滚轮缩放时窗口一起缩放。
置顶在启动/菜单切换时声明一次，并同步 SDL 的 `always_on_top`；主循环只做只读
`WS_EX_TOPMOST` 检查，只有该位真的被 SDL/其他路径抹掉时才补一次 `SetWindowPos`。
Windows 不提供“永远压过所有其他 topmost 窗口”的保证，其他置顶覆盖层仍可能压上来，
此时重新点一次置顶即可，不再周期性抢 z-order。
桌宠窗口状态（透明度/置顶/鼠标跟随/穿透/缩放/位置）存 `state/desktop-<stage.port>.json`；
可见 alpha 包围盒另存 `state/desktop-<stage.port>.rect.json`，只给截图去重掩码用。
Inspector 的远程调参只对**物理输入**参数写 saved 值；物理输出（头/头发/衣服）只覆盖当帧，
不把物理状态每帧固定成常量，避免局部闪烁。
浏览器端没有鼠标跟随。桌面窗在自主驱动开启时把鼠标位置作为 `Context.pointer` 交给注视控制器；
关闭自主驱动时直接按 `profile.by_channel` 写 eye/head/body，不调用 Cubism `Drag`（它只覆盖
标准 `ParamAngle*`，对本模型的自定义上半身参数无效，且会和程序化跟随形成两套来源）。
`live2d-py` 或 Pygame 起不来时只在日志/`state/desktop-<port>.log` 里提示，直播模式不受影响。
`live2d-py` 是非官方 Cubism SDK 封装；SDK/模型许可见 `THIRD-PARTY-NOTICES.md` 和 `vendor/spine/README.md`。

#### 7.2.1.1 桌面透明窗的硬约束（改穿透/跟随/抽动前先读）

**跨进程点击穿透**

- `WM_NCHITTEST` 返回 `HTTRANSPARENT` 只保证把鼠标交给**同一线程**的下层窗口；
  `WS_EX_TRANSPARENT` 单独使用也只影响同进程兄弟窗口的绘制顺序。两者都不能让点击
  落到浏览器/游戏等别的进程。
- 跨进程穿透的唯一可靠开关是 **`WS_EX_LAYERED | WS_EX_TRANSPARENT`**。设置
  `WS_EX_LAYERED` 后必须立即调用
  `SetLayeredWindowAttributes(hwnd, 0, 255, LWA_ALPHA)` 初始化；不调用会让 layered
  窗口默认完全不可见。这里使用系统重定向合成，不使用 `UpdateLayeredWindow`，所以
  OpenGL + DWM per-pixel alpha 仍有效。
- 穿透位只改 `GWL_EXSTYLE`。**禁止**在切换时调用 `SWP_FRAMECHANGED`：它会让 DWM
  重算非客户区/重建重定向表面，表现就是一帧整窗闪烁或抽动。穿透切换放在
  `pygame.display.flip()` 之后执行，避开 DWM 采样窗口表面的时机。
- `Window._on_message` 只做两件事：`WM_ERASEBKGND` 返回 1，`WM_MOUSEACTIVATE`
  返回 `MA_NOACTIVATE`。**禁止**在 WndProc 里调用 `model.hit_part()` 或其它模型方法：
  `WM_NCHITTEST`/鼠标消息频率很高，原生模型调用会进入窗口消息热路径。
- 命中判断在主循环每帧做一次：`GetCursorPos + ScreenToClient + model.hit_part()`。
  进入模型立即摘穿透位；离开模型或移出窗口后要 120ms 防抖再挂回穿透位，避免角色
  呼吸/发梢边缘让命中在真/假之间来回跳变。菜单打开或拖动窗口时强制整窗可点。
- 置顶只在启动/菜单切换时声明一次，并同步 SDL 的 `always_on_top`；主循环只读检查
  `WS_EX_TOPMOST`，只有该位真的丢了才补一次 `SetWindowPos`。不要周期性抢 z-order；
  Windows 不保证永远压过其他 topmost 窗口。

**鼠标跟随**

- `WS_EX_TRANSPARENT` 生效时 Pygame 收不到 `MOUSEMOTION`。鼠标跟随必须每帧从
  `GetCursorPos + ScreenToClient` 更新 pointer，不能只在 `pygame.MOUSEMOTION` 里更新；
  否则 pointer 会冻结在离开模型时的旧坐标，重新进入模型时单帧跳变。
- 自主驱动关闭时不要调用 Cubism `Drag`：它只覆盖标准 `ParamAngle*`/
  `ParamBodyAngleX`，对自定义上半身参数无效；程序化写 `profile.by_channel` 的
  eye/head/body，并写入 `SetSaveParamById`，不要再叠加 `Drag` 形成两套头部来源。
- 自主驱动开启时 pointer 交给 `GazeController`；垂直移动鼠标时，pointer 经过
  `GazeController`、`SpringBank`、`Live2DWriter` 到模型，任何一层都不应做
  “清空 pointer 再重建”的阶跃操作。

**整窗抽动**

- `ParamSpec.to_raw()` 在 `gamma < 1` 时，`|v| -> 0` 的导数趋于无穷；头部平滑过中线
  会被放大成单帧角速度尖峰。当前在 `|v| < 0.08` 内线性过零，之后才走幂函数；不要
  改回全局 `|v|^gamma`。
- 非自主模式**保留** `SetAutoBreath(True)` 和模型自带 idle motion。不要为了压抽动关闭
  呼吸或 idle：那会让尾巴等物理链失去激励，看起来像“不抽了但也不动了”。模型自己的
  呼吸/idle 是跨模型通用激励。
- `CubismBreath` 与 idle 循环边界可能漏出一帧 `head_x/y/z`。当前在 `Draw()` 前用
  二阶差分做窄范围毛刺限幅；每帧记录**未过滤的原始值和速度**，clip 后不会把结果当成
  下一帧起点而持续锁死。跟随鼠标时跳过 head 保护，避免拖慢真实跟随。
- 物理输出（尾巴 `Param_Angle_Rotation84..89`、胸/裙等）不能锁死，也不能写入
  `savedParameters`。`Live2DWriter` 只把**纯 `physics.inputs`**（不在 `physics.outputs`
  里的参数）写 saved；物理输出可以在 `Draw` 前做同样的二阶差分毛刺保护，但不能做
  全局参数限幅，否则会把正常动作/物理一起压慢。
- 传给 `Model.Update` 的 dt 做 EMA 平滑并夹在 1/75–1/45 s；每帧只调用一次 `Update`，
  不拆物理子步（拆子步会让 `LoadParameters`/`SaveParameters` 次数失配）。命中仍用模型
  hit test，**不要**用读整帧 alpha 做命中；只为截图掩码在 `Draw()` 后以 1 Hz 读一次
  alpha 包围盒（同步回读有代价，因此不跟帧、不用于点击判定）。
- `MotionEngine` 的 idle action（约 4.5–9.5 s、75% 概率）是设计行为，不是抽动。不要
  为了压抽动全局降低 idle 动作强度或反向蓄力；只有实测确认是某个动作包络问题才改。

**验收顺序**

1. 空白处能点到背后程序；模型处点击触发 Brain；开启“左键穿透”后整窗穿透、右键/滚轮仍可用。
2. 非自主模式：尾巴/idle/呼吸自然，头不单帧抽；鼠标在角色外移动时头/眼仍持续跟随。
3. 自主模式：垂直鼠标移动、静止 idle action 下无异常单帧抽动。
4. 菜单、拖拽、滚轮、置顶、DPI/副屏恢复不回归。

### 7.2.2 角色设定：`persona/roles/<id>/`

一个角色 = **形象（`models/` 里那套模型）+ 角色设定（`persona/roles/<角色 id>/`）**。
`config.yaml` 只存 `role.id`；切换时两者一起换，**TTS/LLM/直播/记忆等设置不动**。
运行时在记忆库 meta 里记录上一轮的 `role.id`/`user.id`；下一轮 id 变化时，在本轮材料前
插一条 system「身份切换」提示，让模型知道上一轮和这一轮属于不同设定。只改人设内容、
id 不变时不插提示。`role.id` 切换仍需重启 runtime，提示会跨重启保留。

```text
persona/
├── presets/<preset_id>/      # 对话预设（所有角色共用）
│   └── preset.yaml           # name / desc / blocks[]（slot + role + live + text；同一 slot 按书写顺序）
├── roles/<role_id>/          # 这个角色自己的全部内容
│   ├── profile.yaml          # model / name / bot_name / aliases / stage（外观）
│   ├── persona.md            # 人设：这个人是谁；没写就是空，不继承
│   ├── actions.md            # 模型资产词表
│   └── motion_profile.json   # 自主驱动配置（可选）
├── users/<user_id>/          # 用户人设
│   └── profile.yaml
└── games/<game_id>/          # 游戏知识包
    ├── core.md
    └── entries/*.md
```

`persona/` 整体不入库，仓库里没有 base，也没有用户/游戏示例。**本机的
`persona/roles/deepseek/` 是默认角色设定目录（`role.id` 的默认值，对应默认图
`models/images/deepseek.svg`），也是当前唯一的基础示例**（`persona.md` + `profile.yaml`），
配套的默认预设是 `persona/presets/default/preset.yaml`；默认图不存在时 `role.id` 会回退到
扫描到的第一套可用形象，此时 `persona/roles/deepseek/` 不会被读取。
其它角色没有写文件就是空，不从它继承。新机器上要先放回这两份，prompt 里才有人设与规则。

`profile.yaml` 字段：

| 字段 | 谁读 | 空着会怎样 |
|---|---|---|
| `model` | 扫描时按它把角色目录绑回模型 | 按「目录名 = 模型文件夹名」的初始约定绑定 |
| `name` | 「角色设定」页、`/status`、角色下拉 | 显示名回退 `role.id`（不是模型文件夹名） |
| `bot_name` | prompt 的 `{{bot}}`、日志、`brain.stats` | 空 |
| `aliases` | 材料里的「（叫你）」判定 | 空 |
| `stage.cps` | 气泡速度（字/秒） | 用全局默认 |
| `stage.bubble.gap` / `max_width` / `auto_gap` | 气泡间隙 / 最大宽度 / 自动贴头顶 | 用全局默认 |

**没有回退**：角色目录里缺 `persona.md`（或只有空行/注释）就是空；不会去读
任何全局人设，也不会回退别的角色。场合、开口、材料读法、输出契约、去八股、直播追加
全在预设里，角色只用写「这个人是谁」。

**角色外观按角色存**：`stage` 里只放 cps 和气泡间隙/最大宽度/自动贴头顶。
`stage.enabled` / `mode` / `host` / `port` 是全局运行设置，不属于角色，换角色不变
（启用开关在概览页的启用控制里，其余三项在角色页的「形象层」）。
桌宠窗口的形状/大小由形象决定，不在配置里；模型缩放用桌宠滚轮或预览里的整体大小。

**只描述角色**：不含游戏（`game.id` 决定世界书，与"你是谁"正交）、不含用户设定
（`persona/users/<id>/` 是使用者的属性）、不含密钥（角色目录里写 `api_key` 不会被读，
密钥只有 `state/secrets.bin` 一个来源）。

**出错只降级**：YAML 语法错 / 顶层不是字典 —— 记进 `avatar.profile_error`，
该角色按空处理，模型照常能渲染，其它角色不受影响。

**切换要重启**（ADR-09）：WebUI 点选写 `config.role.id`（初始值取模型文件夹名；
之后目录可以改名，绑定看 `profile.yaml` 的 `model`）；运行中的 `AvatarCatalog` 在启动时
`pin()` 钉住当时的角色与快照，扫描刷新也不会换。钉的是 `role_id`，运行中每次重读
用 `roles.active_dir()` 重新解析目录；WebUI 迁移旧指纹目录后不会抱死旧路径。钉住的
模型如果还在但已损坏，继续返回启动快照并保留 broken 状态，不会静默换成下拉里的
另一张脸。
`models/` 为空时 runtime 不再崩：形象为空、动作走 `NullAvatarActions`，原因写进
`/status` 的 stage 错误；语音/脑/弹幕/截屏仍可启动。
原因是热重载要原子替换人设、形象与动作能力，任何一步失败都会出现"新脸旧人设"，直播中很难排查；
重启只要 2 秒，且是一次确定的操作。名字、别名、人设文本是 15 秒内热更；
外观（`stage.cps` / 气泡）和形象能力重启生效。

> `persona/` 整体是个人素材，`.gitignore` 直接忽略；已有文件要提交用 `git add -f`。
> 动作规则 `actions.md` 和 `motion_profile.json` 也属于角色设定，跟着角色目录走。
> `actions.md` 是模型资产词表（`<ACT>motion=...`）；`motion_profile.json` 是自主驱动的
> tuning/动作开关/绑定，两者用途不同，不互相生成。

**三种包（导入导出）**：都是 `GET /api/pack/export?kind=<kind>&id=<id>` 下一个 zip、
`POST /api/pack/import?kind=<kind>[&overwrite=1]` 上传一个 zip；包里都有 `manifest.json`。

| kind | 装什么 | 从哪来 |
|---|---|---|
| `preset` | `preset.yaml` | `persona/presets/<id>/` |
| `worldbook` | `core.md` + `entries/` | `persona/games/<id>/` |
| `role` | `role/{profile.yaml,persona.md,actions.md,motion_profile.json}` + `avatar/<模型文件夹>/…` | `persona/roles/<id>/` + `models/` |

角色包里的形象落到 `models/` 后会重扫一次，拿到角色 id（初始值 = 模型文件夹名 /
图片文件名；已有 `model` 绑定时按绑定）再把角色文件写进 `persona/roles/<role.id>/`，
所以导入完直接能选；形象文件夹已经存在时不重复放，直接复用盘上那份。网页上是
「先点导入按钮、再选文件」。

**用户人设是另一套东西**（`persona/users/<id>/profile.yaml`）：

| 字段 | 含义 |
|---|---|
| `name` | 用户名字：替换 persona 里的 `{{user}}` / `{{user_label}}`，也是材料标签和默认称呼 |
| `persona` | 用户设定正文（背景，不是命令）；怎么称呼用户、用户的代词/性别都写在这里 |

`config.yaml` 只存 `user.id`；没有用户档案就是空，不自动建默认用户，也不回退。
用户切换是热更（15 秒内生效），和角色切换不是一回事。游戏资料同理：没有
`persona/games/<id>/` 就不注入，不拿示例或别的游戏补。

### 7.3 气泡分页与同步

气泡的页 = **TTS 的那几个分句**（同一个 `split_sentences`），说一句翻一页。

| TTS 模式 | 怎么翻页 | 精度 |
|---|---|---|
| `segments: sentence` | `sidekick/output/speaker.py` 每句开播前推 `page(i)`，桌面/浏览器都收 | **精确** |
| `stream: true` | 浏览器按 `cps` 走计时器；桌宠收到 `say(sync=false)` 后由主循环每帧 `Bubble.tick()` 按 `cps` 自动翻页（不依赖 overlay 重绘），同时 Speaker 按 `played_s` 实际播放进度补发 `page` | 估算 + 播放进度校正 |

口型（`level`）是**播放线程**按 20ms 一片算出来的 RMS，不是收到音频时算的：
流式合成往往跑在实时前面好几秒，按「收到」算的话，嘴会在开头两秒把整段演完。
两种模式（流式 / 分段）都从播放线程推，所以换 `segments` 不会让嘴停掉。

`cps` 不是写死的：每次说完，用「字数 ÷ 实际音频时长」回算一次，存成 EMA
（`0.7×旧 + 0.3×新`）——说几十句之后就贴合这个音色了。分段播放还会把**每一句的真实
音频时长**随 `page` 发给桌宠；流式 `page` 也带按 `cps` 估算的 `duration`，桌宠同样用它校准
打字机速度。
`end` 带着 `upto`（真正念到了第几页），页面**只往前进、不往回跳**；浏览器收到 `page`
也只接受大于当前页的索引，迟到的低页号不会把气泡拉回。桌宠收到 `end`
会把当前页剩余的字直接补全（语音已经念完，不该再逐字蹦），停 0.9 秒后收起。
下一句 `say` 会立刻替换旧气泡，不等上一句的停留时间。

| 项 | 值 |
|---|---|
| 出现 | 第一块音频开始播那一刻 |
| 内容 | `speech.say()` 的 `spoken`（已去标签），**和念的一模一样** |
| 阶段提示 | LLM 返回前显示「思考中」；返回后到首块音频前显示「组织语言中」；两者由 `status` 事件驱动，不进入历史 |
| 打字机（浏览器） | 最多 0.6 秒打完一页（字多就快） |
| 打字机（桌宠） | 按本页真实音频时长逐字；没有时长（流式）才退回 `stage.cps`；迟到/重复的同页事件不会重置已打出的字 |
| 停留 | 说完后 0.9 秒 |
| 消失 | 直接收起；下一句开始时立即换内容 |

### 7.4 在直播姬里怎么加

1. 先跑一次自检：直播姬 → 添加素材 → **浏览器** → `http://<stage.host>:<stage.port>/probe`
   （默认地址；实际跟随 `stage.host`/`stage.port`）
   看一眼 `WebGL` 是不是「有」、背景是不是透明的
2. 换正式页：`http://<stage.host>:<stage.port>/`（默认）。气泡和形象的位置/大小读
   **当前角色**的 `persona/roles/<id>/profile.yaml` 的 `stage` 段；没写的字段用
   `config.yaml` 的 `stage` 默认值。改完刷新素材即可，不用重启：

   ```yaml
   # persona/roles/<id>/profile.yaml
   stage:
     bubble:
       gap: <gap>          # 与模型可见头顶的额外间隙（vh），负数压到头上
       max_width: <width>  # 气泡最大宽度（vw），长句在这里换行
       auto_gap: <bool>    # 自动找模型真正有像素的头顶
   ```

   `stage.bubble.auto_gap` 为真时页面会量模型实际有像素的最高点（读 Live2D 画布 alpha），
   把气泡贴到头顶上方。
   `gap` 只是额外留白，不会再被模型画布顶部的透明区域撑远。
   气泡自带 `max-width` + `overflow-wrap:anywhere`，中文、英文、没空格的 URL
   都会在宽度上限内换行，不会从左右跑出画面。

   也可以继续用地址参数临时覆盖：

   | 参数 | 默认 | 作用 |
   |---|---|---|
   | `avatar` | 跟当前选择 | 临时切 Live2D 或图片形象；可写模型文件夹名 / 角色 id / 内容指纹 |
   | `size` | `95` | 形象占屏高度（vh）；只在地址参数里临时调，配置里没有 |
   | `gap` | 见 `stage.bubble.gap` | 气泡和头顶之间的额外间隙（vh），负数会压到头上 |
   | `w` | 见 `stage.bubble.max_width` | 气泡最大宽度（vw） |
   | `auto` | `1` | `?auto=0` 关掉自动贴头顶，只用 `gap` 定位 |
   | `lift` | `0` | 气泡和形象整体上提多少（vh）；同样只在地址参数里临时调 |
   | `scale` | `1` | 仅调试用；界面不再暴露模型缩放 |
   | `cps` | 见 `stage.cps` | 页面本地气泡速度（字/秒），只影响没有 WS 时钟时的预览 |
   | `assets` | `/s` | 前端静态资源前缀 |
   | `preview` | — | **仅 WebUI 预览**：静音、不连 WS，只渲染形象；stage server 没有这个端点 |
   | `debug` | — | 左上角显示：渲染器、音量、口型、页码、报错 |

   WebUI「角色设定」页的预览会自动加载 `inspect.js` 并常驻打开；参数、部件、动作、表情和外观调整会实时同步到已连接的浏览器舞台和 Pygame 桌宠，不改模型文件。图片形象不显示 Inspector。
   `全部复位`清理 Inspector 覆盖、表达式和模型动作并把缩放/位置恢复到加载时的初始取景
   快照；自主驱动关闭时复位后会重新开始模型自带的 idle motion，不会停成一张静图。
   `重载模型`让预览 iframe、浏览器舞台 reload，并让 Pygame 桌宠在同一个窗口/GL
   上下文里关闭并重建模型；三者都回到初始状态，桌宠不会退出进程或销毁窗口。
   Inspector 控制请求在页面上单飞（同一时刻只发一条，参数只保留最新），换角色前先卸载旧预览、
   `pagehide` 时显式销毁 PIXI/Spine；预览地址没变时只更新链接，不重载整个 WebGL 页面。
   连续换角色时用递增的 `S.roleSeq` 只认最后一次响应，迟到的旧角色 profile 不会把页面切回去。

3. 拉到你想要的位置和大小，字号跟着容器高度走，不用改代码
4. 想知道页面这边到底在用什么渲染器、口型有没有被驱动：看 `GET /status` 的
   `stage.report`（页面每 5 秒自报一次，直播姬里看不到控制台，这是唯一的回看手段）

### 7.6 语言 ↔ 画面：`<ACT>` 标签

本地程序解析的表演标签**只有 `<ACT>...</ACT>`**，在 TTS 前剥掉，不进入气泡、历史或
provider 的文本。方括号/圆括号是 TTS 厂商的命名空间（Fish 的 `[whispering]`、MiMo 的
`（小声）`），`<ACT>` 不碰它们。

```text
<ACT>emotion=开心, action=挥手:0.8</ACT>
<ACT>motion=自拍</ACT>
<ACT>expression=开心</ACT>
<ACT>gaze=chat</ACT>
```

- 大小写不敏感；token 用逗号/中文逗号/分号/空格分隔；`key=value` 可带 `:强度`（0–1）。
- `emotion=`/`action=`/`gaze=` 是程序化语义；`state=` 与 `action=` 同义（换装/手型
  状态也走动作目录）；`motion=`/`expression=` 必须写前缀，
  匹配模型 capabilities 里的真实组名/表情名；资产名可以含空格（解析到下一个 `key=` 为止）。
  裸 token 先按情绪别名、再按动作别名解析。
- 一个标签最多 4 个意图，一条回复最多 6 个意图；未知名字只剥离并记日志，不抛异常。
  `action=` 先查精确别名，再按词根兜底（`看旁边→look_away`、`晃晃尾巴→wag_tail`、
  `扭扭腰→sway_hip`、`向前倾→lean`）；正文没有标签但含明确动作词时，`AvatarActions`
  会补一个 intent，含“没有/不能/不会”等否定时不会补。
- 解析时记录每个意图在正文里的字符偏移；`Speaker` 按分页字符比例把它归到 `page(i)`。
  `pages` 为空或标签正好在全文末尾时，页码夹在 `[0, len(pages)-1]`，不抛 `IndexError`。
  首句的意图随 `started` 立即触发，后续分句的意图随 `page` 事件触发；流式合成没有逐句边界时，
  按 `字符数 / cps` 估时依次发 `page`。桌面和浏览器都在收到 `page` 时播放该页的资产/语义动作。
- 未闭合的 `<ACT>` 从开口到文本结尾整段丢弃，绝不念出来；标签在句中出现也剥掉。
- `stage.actions.enabled: false` 时 `AvatarActions` 不注入 `actions.md`/通用标签规则，
  解析仍会剥掉 `<ACT>` 但不产生表演意图；情绪/视线也不会触发。自主驱动与它是独立开关。
- 一条回复里的资产和语义走同一条 `acts` 列表：资产给宿主播放，语义交给 `MotionEngine`；
  动作在首块 PCM 写声卡时触发，不比声音早。

`actions.md` 是**模型资产**词表，由 `rules.build_text()` 按 capabilities 确定性生成，
只教 `<ACT>motion=...` / `<ACT>expression=...` 和一句“最多一个动作加一个表情”，
不规定什么时候用。生成结果只进 WebUI 编辑框，不自动写盘；`actions.md` 里的未知资产名
在保存时会 warning，运行时也会剥掉。语义情绪/动作/gaze 的通用词表由
`sidekick/avatar/act_tags.py` 注入输出约束，不依赖模型是否有 motion 文件。绑定运行时
`ModelProfile` 后，输出约束还会按真实通道/状态追加一段“当前形象的身体能力”：
有尾巴才写尾巴，有 `lean_y` 才写前倾，有换装状态才写长裙/短裙/Q 版；模型没有的能力
不会出现在 LLM 面前，也不会被写成合法 `action=`。

**礼物 / 上舰 / 醒目留言**也会推给页面（`{"t":"event","kind":"gift",...}`）：
桌面宿主把它变成一次固定情绪/动作反应，浏览器从当前形象的表情/动作里挑一个；
这条走 `EventBus` 的旁路回调，**不消费事件、不影响调度**。

### 7.7 自主驱动配置：`motion_profile.json`

路径固定为 `persona/roles/<role.id>/motion_profile.json`，不写进 `models/`。
`role.id` 默认取模型文件夹名（重名加后缀），之后与目录名解耦；换模型会产生新角色，
旧 profile 不会被新模型误读。
文件不存在时运行时用参数自省默认值；文件坏（JSON/UTF-8/超过 256 KB）只记 warning，
不读半成品、不读 `.bak`，也不因此关闭自主驱动。

当前运行时实际消费的字段：

| 字段 | 作用 |
|---|---|
| `schema_version` | 只用于诊断/溯源，必须为 1；不做旧版本迁移 |
| `generated_by` | provider/model/时间/是否 fallback，不含密钥 |
| `archetype` | `chibi/standard/realistic/creature/unknown`，只用于展示/调参来源 |
| `tuning` | `MotionTuning` 的增益；`body_gain` 是全身身体通道的全局倍率（1.0 为基准），越界 clamp，详见 `sidekick/motion/tuning.py` |
| `channel_bindings` | 语义通道 → 参数 ID；只允许模型里真实存在的 ID |
| `aliases` | 额外参数 ID → 语义通道；用于给自定义参数补绑定 |
| `actions` | 动作启停/幅度/时长倍率；也允许自定义配方：`aliases`、`pose`、`loops`、`states`、`raw_overrides`、`persistent_raw`、`duration/attack/hold/release`；`enabled: false` 后该动作不会被 LLM 或待机选中 |
| `states` | 模型审计得到的离散状态事实（换装/体型/手型）；运行时按 `StateController` 持久/定时保持 |
| `motion_policy` | 模型 motion 开关/语义映射/所有权参数；`mode` 只支持 `auto`；`model_motions` 里 `action` 命中程序化动作时优先播模型 motion |
| `expressions` | 情绪 → 模型 expression 名；找不到时丢弃 |
| `prompt` | 情绪/动作/gaze 词表、`rules` 与可选的 `usage`（分行的“怎么用”说明）；生成时校验名字必须在目录里 |
| `warnings` | LLM 不确定项，WebUI 展示 |

运行时仍以自省为事实来源：profile 里的参数 ID 找不到就忽略并 warning，不凭空创建参数。
`motion_profile.json` 只在启动时读一次，**应用后需要重启 runtime**，不做热重载。
`actions` 里的自定义配方让 profile 能定义新动作，而不仅是开关内置动作：`pose` 是语义
通道目标值（运行时按模型能力降级/镜像），`loops` 是每通道的 `[幅度, 频率Hz, 相位]`，
`states` 请求离散状态，`raw_overrides` 在动作期间直接写原始参数，`persistent_raw` 交给
`StateController` 跨帧保持，`degrade` 指定通道缺失时折到哪些通道；不管道/参数不存在时
整条丢弃或只写存在的部分。
`prompt` 块会在输出约束里取代通用表演词表（`actions.md` 仍单独教模型资产）；
没有 profile 或 prompt 为空时用 `sidekick/avatar/act_tags.py` 的通用词表。`prompt.usage`
存在时按行展开成“怎么用这些标签”；没有 `usage` 时回退到 `prompt.rules`。禁用动作不会
出现在 profile prompt 的可用动作里（包括通用词表回退）。自定义动作的别名优先于
内建动作的同名别名；`priority` 保留小数（例如 0.6），运行时不再截成整数。
即使 profile 只写了 `rules`、三个标签表为空，运行时也会补通用情绪/动作/视线词表，
避免模型把 `actions.md` 里的模型资产名当成 `emotion=`/`action=`。`rules` 里
“没有尾巴/不能踢腿/不支持前倾/没有模型表情所以不要用 emotion”这类与运行时能力卡
冲突的静态否定句会被丢弃，能力说明始终以当前 `ModelProfile` 的
`by_channel`/`states` 为准；模型没有 expression 资产时，`emotion=` 仍驱动程序化
面部/身体，`emotion_tags` 不会被清空。
旧 profile 里 `tuning.body_gain` 若小于 0.4（旧版的“注视身体分摊”语义），生成校验和运行时都会
按默认 1.0 处理并记 warning；它不再被二次乘到动作上。

审计 dossier 额外带 `followers`（通道 → `{id, scale}`）、`states`（状态名 → 参数 ID/
有效值/持久或定时）、`physics.inputs/outputs/links`（`.physics3.json` 的输入/输出参数 ID 集合，以及
`output → inputs` 边）、
`vtube`（`ParameterSettings` 的 output/input/channel/polarity/effective_range，以及
`Hotkeys`/`IdleAnimation`）、`probe`（隐藏 GL 顶点探针：`available`/`error`/`params`，
每个参数含 `cx/cy/span_ratio/q_ratio/screen_side/moved_drawables`，虚拟物理输入另带
`virtual_input`）、顶层 `screen_side`（参数 ID → `left/right/center`）、
`model.pointer_origin`（眼部探针 `(cx, cy)`，鼠标注视原点）、`by_channel`（实际胜出的
主参数）和 `unmapped.rows`（有 cdi3/VTube/探针证据的未映射
参数，带量程与 `(cx, cy, span_ratio)`）。`motions[]` 带曲线 `min/max/std/discrete` 和
变化最大的 `top_params`；`expressions[].kind` 区分 `expression`/`persistent`/`reset`，
持久换装表情带 `controls[{id,value,default,min,max}]`；`.pose3.json` 的互斥部件组写进
`pose.groups`。生成 prompt 的 `DEFAULT_TUNING` 用 1.0 基准；
`ALLOWED.param_ids` 包含主参数、从属参数、状态参数、未映射候选和表情控制参数，LLM
只能绑定模型真实存在的 ID。

**角色页「自主驱动」区**：显示审计摘要（tier、绑定数、motion/expression 数、warnings），
提供「审计模型」「生成配置」「应用」「删除」。生成是同步请求：子进程审计 → 程序先生成
确定性 baseline（绑定、状态、可用动作、持久换装开关全部填满）→ LLM 在压缩 dossier 上
做增量选择/调参/自定义配方 → 校验/修复（最多 2 次）→ 与 baseline 合并；仍失败就用
baseline。合并时 `channel_bindings`/`states` 以程序事实为准，`kick`/`leg_shift`/
`wag_tail`/`sway_hip`/`lean`/`bow` 和四个换装状态动作不会被 LLM 关掉；模型有腿、尾巴、
前倾或持久换装时能力不会丢。模型自带 idle motion 由程序化待机接管，LLM 不能重新
打开。结果只进预览，不自动写盘。
`.exp3` 被识别为持久换装/配件的，baseline 会生成一对 `persistent_raw` 动作（原名 +
“关闭/收起”别名），跨帧保持，不依赖 6 秒后回弹的 expression。没有内置动作的离散
状态（换外套、尾巴装束、狗尾草）也会补一对 `state_*_on/off` 状态动作。prompt 的三个标签表
按并集合并，LLM 漏掉 `long_skirt/short_skirt/normal_body` 时仍保留 baseline 的全量词表；
alias 允许绑定 `unmapped.rows` 里真实存在但尚未自动映射的参数，不再误判为“不在模型里”。生成配置的 LLM 请求固定 `temperature=1`、`reasoning_effort=max`，不跟随
聊天 profile；首次生成前等待 2 秒、每次修复前等待 3 秒，降低连续长请求打满网关的概率。
生成走 `POST /api/avatars/{aid}/autonomy/generate/stream` 的 SSE：WebUI 依次显示
“审计模型中 → 发送请求中 → 思考中 → 输出中”，模型正文边收边填进预览框；30 秒只约束
**首个流式 token（思考内容或正文）**，超过则失败并给 fallback；收到首个思考 token 后
不再设总超时，后续等正文期间保持“思考中”，正文开始才切“输出中”。上游在首个正文
delta 前断开（例如网关返回不完整 `Content-Length` 的 `ClientPayloadError`）时自动重试
一次；已经收到正文后不重试，避免把半截 JSON 变成两份。
其他 LLM 调用（主对话、摘要、探针等）仍按当前 profile 的温度/推理强度。字段级问题（不存在的表情/别名、越界 tuning 等）会被丢弃或 clamp 后写入
`warnings`，只有 schema 版本、缺必填字段等结构问题才 fallback；生成单次 LLM 预算
比普通聊天长，避免大 dossier 在聊天超时下必然回退。
应用前会再审计一次并按 dossier 校验，结构校验不过返回 issues、不覆盖现有文件。
LLM 不可用、无 key、输出不是 JSON 或 `finish_reason=length` 都走 fallback，不把半截配置落盘。
同一角色同时只允许一个生成请求。

```text
GET    /api/avatars/{aid}/autonomy           当前 profile + 是否存在 + issues
POST   /api/avatars/{aid}/autonomy/audit     只审计，返回压缩 dossier + 摘要
POST   /api/avatars/{aid}/autonomy/generate/stream  SSE 生成：status/delta/result
PUT    /api/avatars/{aid}/autonomy           按 dossier 再校验后原子保存
DELETE /api/avatars/{aid}/autonomy           删除 profile，回到自省默认
```

生成只影响 `motion_profile.json`，不修改模型原始文件；`actions.md` 仍由
`rules.build_text()` 按 capabilities 确定性生成（§7.6），两件事不混用。

### 7.8 Spine：只做动画级

Spine 是**资产路由**，不是第二套程序化骨骼：

- `<ACT>motion=动画名</ACT>` 直接匹配骨架里的动画名；没有名字映射表，不把“挥手”硬翻成
  `wave`。词表就是该骨架的真实动画名，`actions.md` 由 capabilities 生成。
- 显式动作播完回 idle（`idle`/`idle*`/`wait`/`stand`，挑不到就退第一个动画）；idle 循环。
- **不随机播非 idle 动画**：游戏拆包素材里有 `Attack`/`Die`/`Move`/`aim_fire`，随机播会变成
  “桌宠突然开枪/死亡”。桌面和浏览器都只在收到显式 `<ACT>` / 舞台事件时才切非 idle。
- 没有骨骼级程序化、口型、眨眼或连续姿态；多数拆包模型没有嘴/眼皮骨骼，不保证这些能力。
- **说话期弹性缩放**：`SpineRenderer.set_mouth(level)` 用一个 3.2 Hz、ζ≈0.45 的弹簧把口型能量
  变成脚底锚点的体积守恒缩放（纵向最多 +2.2%，横向对应 -1.1%）和微剪切；不碰 `.skel` 内部骨骼。
  浏览器侧在 `spine-player.js` 用同一套弹簧/CSS transform 作用在画布上。
- **talk 切轨**：骨架里有 `talk` / `speak` / `idle_talk` / `idle + _talk` / 任意 `*_talk` 动画时，
  说话开始自动循环该动画，静音 240 ms 后切回 idle；显式非 idle 动作播放期间不抢轨。
- **错误层不拼 HTML**：官方播放器 `showError` 会展示模型动画名等可控字符串；3.8/4.0/4.1/4.2
  四份运行时都在写入前做 HTML 转义，避免恶意/损坏的 Spine 包把动画名变成页面脚本。
- `/status.stage.report` 显示当前动画/版本/错误；`Spine` 与 `Live2D` 的 `say/page/end` 同一条链路。
- 2026-11-15 本机现有 8 套 `.skel` 实测：8/8 动画名可读，7/8 有显式 idle 类动画；
  `427_vigil_epoque` 没有 idle，回退到第一个 `Default`。词表差异很大，不能做统一动作映射。

|---|---|

`output_chars` 是输出约束（预设 `after_material` 的条目 + 动作/TTS 规则）的字符数；

WebUI 拉起的 runtime 固定开排查端点；手动 `python -m sidekick --no-debug` 可关（仅排查用，
WebUI 不传这个开关）。不想开形象层就在概览页的启用控制里关掉（或 `stage.enabled: false`）。

## 10.1 密钥怎么存

`config.yaml` 里密钥位置只写 `api_key: sealed`。真值在
`state/secrets.bin`，用 Windows 自带的 DPAPI 加密（`CryptProtectData`）：

- 只有**本机 + 本 Windows 账号**能解开，不需要记密码，不引入第三方库
- 程序启动时 `config.load()` 自动解密填回内存，所有调用点（brain / TTS）一行都不用改
- 明文写在 config 里的 key 会被忽略（只认 `sealed`）；WebUI 是唯一入口，环境变量/命令行都不作为来源
- 文件被拷到别的机器、或者别的用户来读，解不开
- 同一个 `secrets.bin` 可以装所有 API；写入按 id 加锁 upsert，只改当前 API，
  其他 API 的记录不会被整份旧字典覆盖
- 只支持当前嵌套格式（`llm.<profile>.api_key` / `tts.<profile>.api_key` /
  `llm.<profile>.headers.<Header>` / `tts.<profile>.headers.<Header>` / 顶层 `sessdata`）
- 回显与保存时递归清掉任意层级/列表里的 `api_key`、`sessdata` 和敏感 header
  （包括 `body.api_key` 这类非声明槽位），不只处理已知槽位
- `sessdata` 是 B 站登录 Cookie，也存进 `secrets.bin`；生成默认配置时留空，它不是 API key，不阻塞启动。
- 配置保存走原子写；WebUI 只用合并写入（`PATCH /api/config` 带本页路径），删除字段走 `path` + `delete`；
  密钥槽位从旧配置继承，没有整份 replace 接口；没有额外快照，历史靠 git。

**换机器 / 重装系统**：DPAPI 绑用户，旧密文作废。需要在 WebUI 里重新输入 key；
仓库不保存明文备份。

**边界**：DPAPI 防的是"文件被拷走、被别的账号读"，**不防**"有人用你的账号在这台机器上跑程序"——
那种情况下他自己就能解开。这是本地程序的极限，不是实现漏洞。

## 12. 调参速查

| 想要 | 改哪里 |
|---|---|
| 她更主动 / 更安静 | `cadence.*.idle_s` ↓ / ↑（越小越早开口） |
| 她更大声 | `tts.common.gain` ↑ |
| 她别老插话 | `scheduler.min_gap_s` ↑（两轮最短间隔）、`cadence.*.idle_s` ↑ |
| 你说话她老听不清 | `mic.gate_percent` ↓（更灵敏，50–75） |
| 环境吵总误触发 | `mic.gate_percent` ↑（更保守，125–150），靠 STT 的三层过滤兜 |
| 她说话时插嘴打不断 | 看 `/status` 的 `barge.active` 与 `mic.mode`；耳机才默认开，扬声器要显式 `barge.enabled: on` |
| 老被噪声误打断 | `barge.min_ms` ↑、`barge.ratio` ↑（扬声器），或干脆 `barge.enabled: off` |
| 回得更快 | `mic.silence_ms` ↓、`tts.common.stream: true`、`llm.source: deepseek` |
| 画面看细一点 | WebUI 把 `capture.clarity_percent` 调到 83.3% 或 100%；网格大小不受影响 |
| 画面省一点 | WebUI 切 `capture.mode=calm`，或把清晰度调回 66.6% |
| 她一直不说话 | 看 `/status` 的 `brain.error`、`brain.summary_error`；确认模型 key 和网络 |
| 兜底话术太吵 | `errors.fallback_cooldown_s` ↑、`errors.fallback_max_apologies` ↓ |
| 换角色 | WebUI「角色设定」页选角色 → 重启 runtime；显示名/别名写在 `persona/roles/<id>/profile.yaml` |
| 换角色人设 | 「角色设定」页的`角色人设`（只有一个 `persona.md`，只写「这个人是谁」）；下一轮生效 |
| 换语气 / 去八股 / 改输出规则 | 「对话预设」页改条目（`persona/presets/<id>/preset.yaml`），保存后下一轮生效 |
| 看这一轮到底发了什么 | 「对话预设 → 条目」右上角「查看完整提示词」；命令行 `scripts/show_prompt.py` 同源 |
| 角色一键搬到另一台机器 | 「角色设定」页`导出角色包`（带形象 + 动作规则 + 自主驱动配置），对方`导入角色包` |
| 换用户 | WebUI「用户设定」页新建 → 下拉选中 → 点「保存」；`persona/users/<id>/profile.yaml`；15 秒内生效 |
| 换直播模式 | 「直播设置」页第一项「直播模式」开关（`session.live`）；重启生效；关着时预设里 `live: true` 的条目整段不注入 |
| 换声音引擎 | WebUI「说话（TTS）」页选声音/来源 → 保存 → 重启 runtime；声音不随角色切换 |
| 换模型来源 | `llm.source` |
| 记忆太长/上下文吃紧 | `memory.history_max` ↓（热窗条数）；`memory.summarize_every` 要小于它 |
| 她记不住旧事 | `memory.recall_episodes` ↑、`recall_min_score` ↓；先在记忆页下载语义模型 |
| 召回太杂 | `memory.recall_min_score` ↑、`recall_strong_score` ↑ |
| 世界书总被想起来 | `memory.recall_worldbook` ↓ 或设 0 |
| 不想用程序化驱动 | `stage.autonomy.enabled: false`，重启 runtime；回到模型 motion + SDK 自动眨眼呼吸 |
| 换语义模型 | 记忆页下载/选择 → 重启 runtime；换模型后旧向量自动重建 |
| 换游戏 | 先在 WebUI「游戏资料」页新建/选择，下拉只显示游戏 id；目录固定 `persona/games/<id>/`（`core.md` + `entries/`） |

## 13. 目录

### 13.1 每个目录是干什么的

| 目录 | 是什么 | 谁会用 |
|---|---|---|
| `sidekick/` | **程序本体**。按 `app` / `config` / `core` / `input` / `scheduling` / `brain` / `memory` / `output` / `avatar` / `webui` / `diagnostics` 功能包划分 | 运行时 |
| `sidekick/output/tts/` | 声音出口。两个 wire（`http` / `edge`）+ 厂商 preset 数据；加同形状厂商只改 `sidekick/config/tts_presets.py` | 运行时 |
| `sidekick/motion/` | 程序化姿态内核：参数自省、顶点探针、弹簧、眨眼、注视、呼吸、情绪、动作、LPC 口型、分层合成；不依赖模型动作文件 | 桌面/浏览器宿主 |
| `overlay/` | **形象层前端**（纯前端）。页面 + Live2D canvas，被直播姬的浏览器素材加载 | 直播姬 |
| `models/` | **形象素材**。`<角色>/` 文件夹 = 一套形象（Live2D / Spine），单张图片放根目录或 `images/`；默认那张兜底图也在这里，内容除它以外不入库 | 你放模型 |
| `persona/` | **预设/角色/用户/游戏资料**：`presets/<id>/`、`roles/<id>/`、`users/<id>/`、`games/<id>/` 全部在本机，整体不入库；没有 base，也没有用户/游戏示例 | 你调语气 / 换游戏 |
| `scripts/` | **自检 / 打印入口**，全部 import `sidekick` 里的模块，没有独立逻辑 | 你排查问题时 |
| `state/` | 运行态：`deepsidekick.db` 记忆库、`said.jsonl` 播出记录（不设上限，由用户手动清理）、`secrets.bin` 加密的 API key、`fallback/` 预录音频、`asr/` 识别模型（SenseVoice 239 MB，删了要重下）、`embed/` 语义模型（int8 1.12 GB） | 程序自己写 |
| `vendor/blivedm/` | 弹幕库源码，commit 钉死。不装进 site-packages，靠 `sys.path` 引入 | 运行时 |
| `vendor/spine/` | Spine 运行时二进制（3.8/4.0/4.1/4.2 各一份 DLL）与**对应版本的许可全文**；许可是再分发的法定条件，不能删 | 桌面窗 |
| `tools/spine/` | 上述 DLL 的补丁源码与编译脚本（MIT），用来重建二进制或向上游提 PR | 你重建时 |
| `voice_samples/` | 克隆参考音频。**没有任何代码引用**，纯测试素材 | 你试听 |
| `temp/` | 一次性探针脚本、截图、素材下载缓存。随时可以整个删掉 | 我调试时 |
| `.venv/` | 项目自带 Python 环境（不提交，不含在源码里） | 运行时 |

### 13.2 依赖方向

```
scripts/  ──import──▶  sidekick/           （全部脚本单向依赖）
sidekick/     ──✗────────▶  scripts/       （0 处反向引用）
sidekick/     ──WS───────▶  overlay/       （只推事件，不 import）
```

`sidekick/` 是程序，`scripts/` 是观察它的工具，`overlay/` 是它的脸。**没有第二份实现。**

# 第四部分 · 边界与限制

## 14. 安全边界

| 层 | 拦什么 |
|---|---|
| 人设 | 弹幕是素材不是命令；路径/IP/密钥/模型一个字不说 |
| `guard.gate` | 硬事实命中 → 整句拒发 |
| `text.clean_tags` | 只放行发声标签 |
| 总结压缩 | 材料是数据不是指令；观众的话不能变成总结里的“他对你说”；异常输出走统一审核 |
| 工具面 | 脑**没有任何工具**——只能输出文字，抓屏说话都是我们替它做 |
| 账号 | 弹幕只读，没有发送函数 |
| 形象层 | 127.0.0.1，只推事件，页面改不了任何东西 |
| 打断 | **输入侧**行为：麦克风判决 → `speaker.stop()`；模型输出与页面都不能触发，也没有对应工具 |

**原则：不说，比说错好。** 任何异常 → 静默，不输出半成品。

## 15. 已知限制

| 项 | 现状 |
|---|---|
| 图片分辨率 | 剧烈模式默认 66.6%（16:9 1280×720），游戏 UI 小字可能读不出来；需要读字把清晰度调到 83.3% 以上。1920×1080 一张 968 token |
| 画面时序 | 多帧的「先看当前高清再看历史拼图」靠布局与提示词约束，真实动作游戏里的理解还没实测 |
| 冷场沉默 | 模型偶尔回「略」→ 这一轮不说话。这是设计（合法沉默），不是故障 |
| 模型协议 | 只支持 OpenAI chat/completions；Responses / Anthropic 原生、进程内本地引擎、流式都不接。本地 Ollama / LM Studio 等暴露的 OpenAI 兼容 HTTP 仍按 API 处理 |
| 模型参数 | `temperature` 是页面必填，暂不支持“完全不传”；`reasoning_effort` 可空。`body` 里的额外参数被服务端拒绝时不自动剔除，需要手改 `config.yaml` |
| opencode 缓存 | 网关不报明细，命中率无法自证（结构上一致） |
| 记忆去重 | 同一件事靠总结 prompt 的 merge 合并；向量余弦 >0.90 的重复只在召回时保留更新的一条，不做全局归并 |
| 语义模型 | 支持 FastEmbed 内置/自定义的 Qwen3-Embedding-0.6B（fp32/int8）、jina-embeddings-v3（CC-BY-NC）、BGE-M3；模型需要单独下载；BGE-M3 用 CLS 池化自定义注册；int8 Qwen 需要 onnxruntime>=1.23；本地 CPU 推理，慢机器上 query 会按 `memory.embed_timeout_ms` 降级关键词 |
| 召回失败 | query 超时/模型缺失时只走关键词 + 近因，不沿用上一轮召回；不做拼音/BM25/第二段 LLM 召回 |
| 回声 | 无 AEC；播放期照常进 VAD，TTS 漏音可能被识别。耳机下靠 `barge` 停播，扬声器只有显式 `barge.enabled: on` 才按能量比打断；要边说边打断建议戴耳机 |
| 截屏后端 | 优先 dxcam（DXGI，独占全屏也能抓）；它不可用时退回 PIL，而 PIL 抓独占全屏的游戏只有黑屏——无边框窗口不受影响。smoke_capture.py 存的那张图就是用来确认这件事的 |
| 多音色 | 不支持动态切换——两套音色会让直播间听起来像两个人 |
| TTS 来源 | 只支持 HTTP API 型厂商；不内置 GPT-SoVITS / CosyVoice / piper 等本地推理引擎。音色 ID 需要从厂商页面复制，音色列表接口未做 |
| TTS 新协议 | 只覆盖 REST / SSE / 裸音频；Azure SSML、WebSocket 二进制、Gradio 自建、返回 URL 再下载都不在本轮 |
| 形象许可 | 仓库不附带 Live2D / Spine 模型；使用者自己放入的模型各有许可，直播/商用前要自行确认（本机若用 NC 模型，开打赏就不合规）。见 §7.5 |
| VTube 证据 | 只读模型目录内的 `.vtube.json`；作者写了但当前模型不存在的输出参数只保留在审计里、不绑定；反相/有效区间以作者声明为准，和 `.moc3` 不一致时不自动仲裁 |
| 关节链 | 数字编号 `Leg*1Z/2Z/3Z` 按 1=髋、2=膝、3=踝解释；只有三个关节都唯一绑定且探针 `cy` 足够分明时才自动重排，否则只 warning |
| 浏览器物理 | 只对胸/裙/尾等次级物理叶结点做 `add` 叠加；头发等纯物理输出仍完全不写，浏览器不读回物理结果 |
| GL 帧缓冲的 alpha | SDL 建的 OpenGL 窗口**默认没有 alpha 通道**（实测 `GL_ALPHA_BITS=0`），且是拿到窗口后才看得到。凡是用到 alpha 的地方都要先 `gl_set_attribute(GL_ALPHA_SIZE, 8)` 再 `set_mode`，并且**别把 alpha 当成一定存在**——早期逐像素透明方案就是在这里一路呈现"黑窗"，最后改用 DWM 合成才绕开 |
| Spine 版本 | 只支持 3.8 / 4.0 / 4.1 / 4.2（各带一份运行时）；3.5/3.6 的许可不允许分发，3.7/4.3 未验证，扫描阶段直接标"不支持" |
| Spine 能力 | 没有口型、没有表情（格式里没有 expression 这一节），全部按动作处理；`.skel` 的动画名要等形象被选中时才读（首次约 0.1 秒）；物理参数只能在 Spine 编辑器里调 |
| Spine 预乘 | 图集写了 pma: 就照它；没写（3.8 导出、部分 4.x 导出）才按像素违例比例判，阈值 1%。判定在**服务端**做（与桌面渲染器共用 sidekick/spine/pma.py），浏览器只读 /config.json 的 pma——canvas 的 getImageData 会把预乘图解预乘再交回来，自己判永远得到“预乘”；无法判定时按 PMA 处理 |
| Spine 浏览器舞台 | 与 Live2D 同一条舞台链路；渲染交给**官方 Spine Web Player**（按骨架版本动态加载，命中一个只下载一份），我们只做版本嗅探/取景/控制适配 |
| 桌面点击穿透 | 常驻 `WS_EX_LAYERED | WS_EX_TRANSPARENT`，空白处跨进程穿透；模型内由 `_handle_hit_through()` 的 120ms 离开防抖恢复可点。`WM_NCHITTEST` 不调用模型，只由 `WM_ERASEBKGND`/`WM_MOUSEACTIVATE` 做窗口级处理 |
| 桌面窗口抽动 | 穿透位只改 `GWL_EXSTYLE` 且在 flip 后切换；常驻 layered/noactivate，拦截 `WM_ERASEBKGND`/`WM_MOUSEACTIVATE`。保留模型原生 idle/呼吸，用每帧 Win32 光标跟随、`gamma` 过零线性化、物理输出 saved 排除、dt EMA、head 角度/尾巴物理输出的二阶差分单帧毛刺保护来压住边界尖峰。 |
| 置顶 | `WS_EX_TOPMOST` 在启动/菜单切换时声明一次并持续保留；Windows 不保证永远压过其他 topmost 窗口（直播姬/游戏覆盖层可能再压上来），此时重新点一次置顶即可，不再周期性抢 z-order |
| 网络 | fish 和 pypi 走 TUN 的 fake-IP 会被重置，需要走本地代理；deepseek / opencode 不受影响 |
